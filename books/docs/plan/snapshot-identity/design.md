# 快照身份：迭代设计

> **状态：阶段 1 已落地**——`manifest.json` 已有身份段、快照按书归目录、`diff` 默认拒绝跨书比对；
> 阶段 2（旧快照补身份、跨源对比报告）待做。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**让每份快照自证「我是哪本书、哪棵源树、哪个工具版本」**——换书或换源码树之后仍可安全比对。

---

## 1. 问题

工具链支持换书、换被分析的源码树，但 `data/snapshots/` 里的快照是无名产物：

| 现象 | 后果 |
| --- | --- |
| 目录只有 `<date>-<label>`，manifest 只有 `date/source_archive/edition/files` | 同一天两本书各做一份，谁也说不清哪份是哪本 |
| 没有源树身份 | 换了 `[sources]` 之后，旧快照与新构建的差异分不清是「书改好了」还是「换了个被分析对象」 |
| 没有工具版本与配置指纹 | 同一份手稿两次构建结果不同时，无法判断是否因阈值或排版配置变了 |

## 2. 目标与非目标

**目标**：快照自证身份（书、源树、工具、语言）；同一天不同书不冲突；比对前先比身份。

**非目标**：不做跨书内容语义比对（那是人的判断）；不迁移旧快照的正文（只补身份，能补则补）。

**硬约束**：身份字段全部取自现有来源（`book.toml`、`[sources]`、`_version.py`、配置指纹），
不新增需要人工维护的副本；旧布局（平铺目录）必须仍可读。

## 3. 身份块

| 字段 | 取值 | 用途 |
| --- | --- | --- |
| `book.slug` | `book.toml [book].merged_name` | 目录命名与列表首列 |
| `book.version` / `book.edition` | 文档版本轴、删节版标记 | 同一本书跨版本比对时区分 |
| `source.roots[]` | `[sources]` 的 label/path/version | 说明分析的是哪棵源树 |
| `source.version` | 被分析源码版本 | 换源树的直接证据 |
| `tool.version` | 工具链版本 | 构建行为差异的第一嫌疑 |
| `tool.config` | 三份策略文件的哈希指纹 | 阈值/排版变化可追溯 |
| `language` | 语言包代码 | 语种一致才谈得上文字对比 |

## 4. 取舍

- **目录按书分空间，而不是靠 label 里手写书名**：手写会漂移，目录不会。
- **`diff` 默认拒绝**：跨书增量写成「退化」比拒绝更糟；`--cross` 放行但先声明「不是退化」。
- **旧快照不重写**：身份缺失显示为 `legacy`，并因此落入「默认拒绝」——不知道对象就不比，是可以接受的保守。
