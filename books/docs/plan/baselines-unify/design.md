# 基线目录归一：迭代设计

> **状态：实施中**——信封、命名、键形态与源版本校验一次统一，旧名保留读取兼容。
>
> 软件：bookwright — 源码分析成书工具 v0.2-dev
> 版本：v0.2-dev
> 定位：**让 `data/baselines/` 的每个文件自证「哪道门禁、什么形态、按什么键记账、哪天记的」**。

---

## 1. 问题

同一目录里长出了四套后缀（`-baseline` / `-findings` / 裸名）、三种信封（`accepted[]`、`files{}`、
两个私有结构）和两种键写法（带 `data/manuscript/` 前缀 / 只有文件名）。后果不是美观问题：

| 现象 | 后果 |
| --- | --- |
| 后缀表达形态而非门禁 | 看目录说不出谁在读它，`grep` 才能回答 |
| 信封各自为政 | 无法写一个通用清单/校验命令，只能逐个特判 |
| 键形态不一 | 手稿目录一挪，一部分基线整片失效，另一部分继续命中 |
| `source_version` 记了不校验 | 上游换版本后仍沿用旧承认，漂移静默通过 |

## 2. 目标与非目标

**目标**：一个信封、一种命名、一种键形态、一条源版本校验；旧文件仍可读。
**非目标**：不改任何门禁的判定逻辑与阈值；不改变存量的条数（迁移前后必须一致）。

## 3. 信封与命名

```json
{
  "schema": 1,
  "gate": "captions",
  "kind": "accepted",
  "keyed_by": "manuscript-path::rule::text",
  "updated": "2026-11-27",
  "note": "…",
  "accepted": ["ch1-2-architecture.md::1-1"]
}
```

`kind` 三取一：`accepted`（已审的存量按键）、`counts`（每文件计数）、`records`（成段读数，如耗时/体积）。
文件名统一为 `<gate>.json`，由 `base.json [baselines]` 声明；旧名只读兼容，重记一次即迁移。

## 4. 取舍

- **键统一为手稿相对路径**：`data/manuscript/` 前缀不再进键，目录搬家不会让基线整片失效。
- **源版本校验只提示不失败**：版本不符时门禁仍通过，但打印「上游已换版本，请复核并重记」，避免旧承认被当成新结论。
