# 依据化：迭代设计

> **状态：未开工**——本文是设计文本；判据与分析器均未改动。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**让每条强断言有依据、让分析器产出可直接引用的依据**——claims 判据与三类新事实块。

---

## 1. 问题

现在手稿里的强断言（「总是」「不会」「保证了」）没有任何强制依据：`source_refs` 只校验**已写出**的
坐标是否过期，不检查断言是否有坐标。同时分析器只抽包/类型/API/依赖/坐标五类事实，失败路径、
不变量、调用链这些「读者最想知道的依据」根本没有产出。

## 2. 目标与非目标

**目标**：强断言要么挂坐标/事实块引用，要么被报告；分析器新增 `failure`、`invariants`、`paths` 三类
事实块，供正文引用。全部按语言适配器实现，换树只换 `[sources]`。

**非目标**：不做语义理解级判据（不判断断言是否「正确」，只判断是否有依据）；
不做跨语言的统一调用图（先在每门语言内做，`paths` 允许缺省）。

**硬约束**：抽不到就缺省为空块，判据对空块不报错；坐标解析沿用 `sources.suffixes`。

## 3. 判据与事实块

| 对象 | 内容 | 判据 |
| --- | --- | --- |
| `claims` | 含强断言的句子 | 句内或同段内有坐标/事实块引用，否则报告 |
| `failure` | 每包的错误类型、抛出点、返回码 | 条数下限（按包规模）；被正文引用 |
| `invariants` | assert/check/require 与 must/never 注释 | 存在即产出；被正文引用 |
| `paths` | 入口 → 关键 sink 的调用链骨架 | 每条路径首尾可解析到坐标 |

## 4. 风险

- 强断言的识别靠句式，会误报；缓解：词表进语言包，报报告而不是直接红。
- `paths` 依赖静态调用解析，虚调用/反射会断链；缓解：断链处标注「静态解析中断」，不猜。
