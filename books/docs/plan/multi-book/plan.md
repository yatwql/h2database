# 多书并行维护：实施步骤

> 定位：`design.md` 的落地顺序。每一步都以「当前单书行为与产物不变」为前提，
> 每步独立可交付、可回滚。

## 步骤一：配置按书解析（已完成）

**动作**：`lib/_config.py` 的十余个导入期常量改为 `Config(root)` 的值与行为；
模块级名字经 PEP 562 转发到「活动书」，新增 `current()` / `use()` / `for_root()`。

**验收**：调用形式与取值不变；渲染文本哈希不变；新增用例钉住两本书互不串值、
`use()` 异常也还原、未知名字仍报错、缺 `book.toml` 仍是 `ConfigError`。

## 步骤二：`--book` 与向上查找

**动作**：

1. `core/actions.py` 的入口增加 `--book <目录>`；未给时从当前工作目录向上找
   `data/book/book.toml`，找到即以其所在树的书根为准。
2. 选定后全程在一个 `with _config.use(cfg):` 里跑，不再有任何模块读环境变量二次推导。
3. TUI 与 Web 增加书目选择屏；单书时隐藏该屏。
4. 日志文件名带上书标识，`data/state/`、`data/baselines/`、`dist/`、`logs/` 落在各自书根。

**验收**：同一台机器上两本书交替跑 `analyze` 与 `check`，互不覆盖；不带 `--book`
时行为与今天完全一致（同样的产物、同样的日志位置）；缺 `book.toml` 时给出可读错误
而不是堆栈。

## 步骤三：手稿的 edition 轴

**动作**：

1. `data/manuscript/<edition>/` 成为默认形态（单版本时 `edition = "main"`）；
2. `book.toml [editions]` 声明版本清单，`--edition` 选择；
3. 派生状态与体量基线按版本分键（`state/<edition>/`、`baselines/<edition>.json`）；
4. 门禁报告标注版本，跨版本比对显式要求 `--compare-edition`。

**验收**：两份手稿各自的体积基线与状态互不污染；`content-volume` 不会拿甲版本的下限
判乙版本；默认（未指定 edition）路径与今天一致。

## 步骤四（条件成熟时）：工具链独立成包

**动作**：`src/python/` 抽成带 `pyproject.toml` 的包，默认配置随包分发，
`--book` 由「向上查找」改为必填；本仓只剩书目录与文档。

**前提**：步骤二的路径全部由注入得到，模块内不出现「从工具位置推导书根」。

**验收**：把书目录单独复制到别处，安装后的命令仍能完整跑 `check` 与 `deliver`。

## 顺序理由

步骤一是所有步的公共前提（没有按书解析的配置，其余都只能靠环境变量），
步骤二让「一个进程读多本书」成立，步骤三才解决「一本书多份手稿」。
步骤四只是把工具链换个交付形态，不改变任何判定口径。
