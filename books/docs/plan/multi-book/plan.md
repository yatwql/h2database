# 多书并行维护：实施步骤

> 定位：`design.md` 的落地顺序。每步独立可交付、可回滚，且以「默认单书行为不变」为
> 前置条件。验收写成可机检的判据，不写「体验更好」这类无法判定的说法。

## 步骤一：配置按书解析

**动作**：配置以 `Config(root)` 表达，模块级名字转发到活动书，
新增 `current()` / `use()` / `for_root()`。

**验收**：调用形式与取值不变；渲染文本哈希不变；`test_lib_config_books.py` 的 8 条用例全绿
（两本书互不串值、嵌套与异常都还原、未知名字报错、缺 `book.toml` 报 `ConfigError`）。

**回滚**：无数据形态变化，回退代码即可。

## 步骤二：`--book` 与向上查找

**前置（必须先做）**：

1. `source_refs.SOURCE_DIR`、`content_depth.source_root`、`chapters.SOURCE_ROOT` 三处在
   导入期就把源根固定，切书对它们无效。改成调用时读取，并加一条用例：在同一进程里
   `use()` 切到另一个书根后，这三处返回的源根随之改变。
2. `lib/_config` 的 `_DEFAULT` 在导入期构造，那时 `--book` 还没解析；它必须惰性化（首次
   `current()` 才构造），入口先定书根再构造 `Config`。这条不改，`--book` 只在一部分
   调用路径上生效。
3. 与第 2 条配套：消费方不得在模块顶层读配置（`SOURCE_ROOT = _config.source_tree(...)`
   这类赋值会让惰性失效）。除上面三处，`check_architecture.py` 新增一条机检——模块顶层
   出现 `_config.<属性>` 取值即失败——把这一类问题挡在入口之前。

两条不改，步骤二只是「看起来切了书」。

**动作**：

1. 两个入口都增加全局参数 `--book <目录>`：`app/cli.py`（经 `scripts/bookctl` 包装，含
   `bookctl make --book …` 的透传）与 `make.py`（CI 走它）。未给时从当前工作目录向上查找
   `data/book/book.toml`，找到即以其所在书根为准。
2. 优先级固定为：`--book` > 环境变量 `BOOK_ROOT` > 向上查找 > 工具链所在 checkout。
   四者都落空时的报错必须点明「没找到 book.toml，试过哪些位置」。向上查找走到文件系统根
   为止，路径比较用 `realpath`，在大小写不敏感的文件系统上按不敏感比较；书根可以嵌套
   （一本书的 `docs/` 下再放另一本书），向上查找取**最近的一本**，并打印命中的是哪一个。
3. 选定后整次运行在一个 `_config.use(cfg)` 上下文里；三个渠道各自落地（见 `design.md` §8）：
   - `scripts/bookctl` 透传 `--book`/`--edition`（含 `bookctl make …`）；
   - `app/web.py`：顶部「书 / 版本」下拉框（候选来自新增的 `/api/books`），选择随后续
     动作请求发出；服务端把**动作执行**放进全局锁，锁内 `use(Config(book), edition)`
     并在结束时还原；找不到书时页面给可读错误，不显示堆栈；
   - `app/tui.py`：对象行在多书时补书根；「切换书籍」放进「配置与状态」二级屏，候选为
     向上查找命中的书与同仓并列的兄弟书（只列能读到 `data/book/book.toml` 的目录），
     数字键直选、`0` 返回；有动作在执行时拒绝切换；切换后清空结果区与状态摘要；
   写配置的动作（`settings set`）写到活动书自己的文件里，不跨书、不跨版本。
4. 缺 `data/book/book.toml` 的书根：退出码 2，报出路径与期望文件名，不打印堆栈
   （退出码沿用 `core/actions.py` 的既有约定：未知动作与配置异常都退 2）。`book.toml`
   只认 `data/book/`，不自动回退到旧位置。
5. 书根校验：`book.toml [paths]` 的每一项都必须落在书根内（拒绝绝对路径与 `..`），
   否则产物可能写到书根之外，两本书就会在同一处撞车。

**验收**：

- 不带 `--book`、在仓库根运行时，`make.py check` 的结论与产物路径逐字不变（渲染文本哈希
  不变）。这条只对「仓库根就是书根」成立：从别的书目录里运行本来就是另一本书，不在等价
  范围内；
- 新增用例：给定两个夹具书根，`--book` 指向第二个时 `_config.BOOK_ROOT`、`state_path`、
  `dist` 全部落在第二个书根下；向上查找用例：在 `data/manuscript` 下运行时命中该书根；
- 新增用例：`--book` 指向没有 `book.toml` 的目录时报错含「book.toml」且退出码 2；
- 优先级用例：同时给 `--book` 与 `BOOK_ROOT` 时以 `--book` 为准；
- 顶层取值的机检白名单在本步完成时为空（三处的顶层取值已移入函数体内），新增违规即判红；
- 改动分档用例：在书 A 的改动、以书 B 为活动书运行时，`check_runner` 不把该改动算作
  `infra`（不触发全量），而是映射到一个可忽略的域；
- 三渠道一致性用例：同一动作、同一本书，`cli` / `web` / `tui` 三条路径给出相同结论；
- Web 用例：请求携带 `book` 参数时被忽略（不改变活动书），页面头部显示启动时选定的书；
- TUI 用例：切换书籍后结果区与状态摘要被清空，且 `_config.current()` 指向新书；动作执行中
  的切换被拒绝；
- Web 用例：`/api/books` 列出两本夹具书；带书参数的动作请求在锁内执行，两个并发请求
  各自拿到自己选的书（断言不串）；页面标题显示当前书与版本；
- 两界面都不记忆上次选择：新进程不带参数时回到 `--book` / 环境变量 / 向上查找的决定。

**风险**：`make.py` 的步骤表通过子进程调脚本，`--book` 必须传达到每个子进程，否则子步骤
退回兜底根。做法是选定后把书根写进子进程的环境变量（`BOOK_ROOT`），与步骤二的第 2 条
的优先级自洽：命令行显式给定者在父进程已解析完毕，子进程只读环境变量。
实现时在 `technical.md` §3.1 记录这条传播方式。

**回滚**：删除入口与相关用例；不涉及数据迁移。

## 步骤三：手稿的 edition 轴

**动作**：

1. `book.toml [editions]`：键为版本标识，值为显示名；**未声明即单版本**，目录形态不变。
   章节清单仍归书级（`[chapters]`），版本默认继承，需要时用 `[editions.<id>.chapters]`
   覆盖。章号按保留章节重编号（`structure.py` 要求 `1..N` 连续），原章号到新章号的映射
   记进该版本的派生状态；图号在各自章节内不变。
2. 声明后，各版本手稿放 `data/manuscript/<edition>/`（`[paths].manuscript` 仍指向
   `data/manuscript`，版本目录在它下面），`--edition` 选择；缺省版本写在
   `book.toml` 的顶层键 `default_edition`（**不放在 `[editions]` 表里**，否则与名为
   `default` 的版本冲突）。只有一个版本时可省略 `default_edition`；两个以上必须声明，
   否则报错而不是「取第一个键」——键的顺序不是接口。
3. 版本级目录按规则派生：状态 `state/<edition>/`、基线 `baselines/<edition>/`（目录内的键
   与当前相同）；未声明 `[editions]` 时仍写 `state/`、`baselines/`。日志不按版本拆
   （`logging.dir` 不变）；数据归档目录带版本：`<slug>-<edition>/<date>/`；快照账本记版本标识。
4. 重编号产出 `state/<edition>/renumber.json`（原章号→新章号），并据此同步改写正文引用：
   `详见第X章《…》`、术语表的章号指引、索引条目里的章号；`index_xrefs.py` 里 1-12 的
   硬编码的 1-12 由该版本的章号集取代（必须在本步一并处理，否则删节版必红）。
5. 产物按版本命名：缺省 `<merged_name>-<edition>`，需要固定名字时用
   `[editions.<id>].merged_name`；同时有语言后缀时再接 `-<lang>`；封面与 manifest
   都记录版本标识与语言标识。
6. `content_volume.py` 的体量比对只与同版本基线比；跨版本比对必须显式给
   `--baseline <文件>`，不允许隐式回退。
7. `--edition` 在三个渠道同样生效：CLI 与 `make.py` 用全局参数，Web 在启动时固定，
   TUI 在「书籍」屏里同时列出版本（一屏两级：书 → 版本）；`--edition` 与 `--book` 一样要
   传达到每个子步骤：`make.py` 的步骤表通过子进程执行，
   父进程解析后把版本写进环境变量（`BOOK_EDITION`），子进程只读环境变量；`settings`
   类动作只写当前活动书的文件，不跨版本、不跨书写。

**验收**：

- 未声明 `[editions]` 的书：`make.py check` 与产物路径不变；
- 声明两个版本的书：两版本的 `state/`、`baselines/` 互不覆盖，`content_volume` 不拿
  甲版本下限判乙版本（用例构造甲厚乙薄，断言乙仅在与自己基线比时通过）；
- `--edition` 指向未声明的版本时报错列出已声明版本；
- `renumber.json` 写在 `state/<edition>/` 且被引用改写与跨版本对照共同使用；
- 两份手稿各跑一次归档，`data/archive/` 下目录名带版本、互不覆盖；
- 未声明 `[editions]` 时 `logs/`、`state/`、`baselines/` 的位置与当前逐字一致；
- 三个渠道都能选到版本：`cli --edition`、Web 启动参数、TUI 屏幕选择，且三者对同一版本
  给出相同结论。

**风险**：

1. `data/manuscript/` 下出现子目录后，`front_matter()`/`back_matter()` 的 glob 会跨版本
   匹配——必须把 glob 根限定到所选版本目录。
2. 重编号会同时动章号、跨章引用、术语与索引三处；任何一处漏改，`crossrefs.py`、
   `index_xrefs.py` 或 `structure.py` 都会判红。用例要各钉一条。
3. 两份手稿的产物名撞车会静默覆盖；命名规则与 manifest 记录要在同一步落地。

**回滚**：删掉 `[editions]` 表即回到单版本形态；`state/<edition>/`、`baselines/<edition>/`
会作为残留目录留着，不影响单版本运行，确认无用后手工删除。

## 步骤四（条件成熟时）：工具链独立成包

**动作**：`src/python/` 抽成带 `pyproject.toml` 的包；默认配置随包分发；
`--book` 必填；本仓只剩书目录与文档。包里必须一并带上三样东西，
否则装完就跑不起来：默认 `book.toml` 模板（供 `bookctl new`）、`templates.toml`、
`language/*.json`。

**前提**：步骤二的路径全部由注入得到，模块内不出现「从工具位置推导书根」；
否则换目录即失效。

**验收**：

- 把书目录单独复制到仓外，安装后的 `bookctl check` 能完整跑通，且结论与仓内运行
  同一本书时一致（不依赖仓内相对路径）；
  PDF/EPUB 交付验收只在装有 pandoc/playwright 的环境执行，缺工具时按既有约定跳过并报出
 跳过原因，不得静默通过；
- 仓内没有「工具目录 → 书根」的推导（`_default_root()` 仅作为交互式兜底，也不被
  任何门禁依赖）；
- 安装后 `bookctl new <目录>` 能在任意位置建出一本可立即 `check` 的书（默认配置、模板与
  语言包齐备）。

**回滚**：包化前后书目录形态不变，回退到仓内工具链即可。

## 步骤五（按需）：多根源与源指纹

只有一本书要同时分析多个源时才做，单源时不做任何改动。

**动作**：

1. `[sources].roots[]`（`label`、`path`、`language`、`version`）与单根 `src_main` 并存，
   `source_tree('src_main')` 返回首根；`label` 必填、唯一，重复或缺失即 `ConfigError`；
2. `source-inventory.json`、坐标报告、日志按 `label` 分组；
3. 体量基线写入 `source{label, version, digest}`，指纹不匹配时报「基线来自另一个源」。

**验收**：单源书 `make.py check` 结论与产物不变；双源夹具书（两个各含一个类的临时源树，
`label` 分别为 `h2` 与 `client`）的 inventory 两棵树的类都能被坐标门禁解析；`label` 重复
时报 `ConfigError`；换源后 `content_volume` 报指纹不匹配而不是静默通过。

**回滚**：删 `roots` 表回到单根；基线里的 `source` 字段留着不影响比对（单根时与
`versions().source` 一致）。

## 每步都要带的文档同步

多书能力会同时出现在五份管理文档里，漏一处就出现两套说法。清单见
`design.md` §12；每一步的验收里都要勾一遍自己那条，`doc_drift` 只兜得住路径与章节名，
兜不住「同一事实两种说法」。

## 四步之外：本仓自举与 CI

- **自举**：B 形态一启用，仓库自己也要变成「各书目录 + 并列的 shared 目录」。这需要一次
  `git mv` 与 `_default_root()` 兜底值调整，单独提交，验收是「门禁全绿、产物逐字不变」。
- **CI**：现有 `book.yml` 按单书跑；多书形态下按书各跑一次即可，不做跨书汇总。CI 的改造
  不在本计划内，但 B 形态不得让单书 job 变慢或变复杂。

## 这几步明确不做

- **不做 `--book` × `--edition` × `--language` 的组合矩阵门禁**：三者各自有判据，
  组合只影响产物命名；为组合写门禁的收益低于维护成本。
- **不自动迁移已有书**：旧布局（`book.toml` 不在 `data/book/`）报错并给出期望路径，
  迁移是一次手工 `git mv` 加一次 `changelog` 记录。
- **不改任何阈值语义**：选书、选版本、选源只决定「读哪个文件、写到哪里」。
- **不做跨书汇总**：没有「一次检查所有书」的命令，多书由外部按书各跑一次。

## 顺序理由

步骤一是其余各步的公共前提（没有按书解析的配置，换书只能靠环境变量加重新导入）；
步骤二让「一次运行服务哪本书」可指定，并顺带把并发边界写清；步骤三才解决
「一本书多份手稿」。步骤四只换交付形态，不改变任何判定口径。
