# 多书并行维护：实施步骤

> 定位：`design.md` 的落地顺序。每步独立可交付、可回滚，且以「默认单书行为不变」为
> 前置条件。验收写成可机检的判据，不写「体验更好」这类无法判定的说法。

## 步骤一：配置按书解析（已完成）

**动作**：导入期常量改为 `Config(root)` 的值与行为，模块级名字转发到活动书，
新增 `current()` / `use()` / `for_root()`。

**验收**：调用形式与取值不变；渲染文本哈希不变；`test_lib_config_books.py` 的 8 条用例全绿
（两本书互不串值、嵌套与异常都还原、未知名字报错、缺 `book.toml` 报 `ConfigError`）。

**回滚**：无数据形态变化，回退代码即可。

## 步骤二：`--book` 与向上查找

**动作**：

1. `app/cli.py` 增加全局参数 `--book <目录>`；未给时从当前工作目录向上查找
   `data/book/book.toml`，找到即以其所在书根为准。
2. 优先级固定为：`--book` > 环境变量 `BOOK_ROOT` > 向上查找 > 工具链所在 checkout。
   四者都落空时的报错必须点明「没找到 book.toml，试过哪些位置」。向上查找走到文件系统根
   为止，路径比较用 `realpath`，在大小写不敏感的文件系统上按不敏感比较。
3. 选定后整次运行在一个 `with _config.use(cfg):` 里；`app/web.py` 启动时选定一本书并在
   进程内固定（见 `design.md` §6）。
4. 缺 `data/book/book.toml` 的书根：退出码 2，报出路径与期望文件名，不打印堆栈
   （退出码沿用 `core/actions.py` 的既有约定：未知动作与配置异常都退 2）。`book.toml`
   只认 `data/book/`，不自动回退到旧位置。
5. 书根校验：`book.toml [paths]` 的每一项都必须落在书根内（拒绝绝对路径与 `..`），
   否则产物可能写到书根之外，两本书就会在同一处撞车。

**验收**：

- 不带 `--book` 时，`make.py check` 的结论与产物路径逐字不变（渲染文本哈希不变）；
- 新增用例：给定两个夹具书根，`--book` 指向第二个时 `_config.BOOK_ROOT`、`state_path`、
  `dist` 全部落在第二个书根下；向上查找用例：在 `data/manuscript` 下运行时命中该书根；
- 新增用例：`--book` 指向没有 `book.toml` 的目录时报错含「book.toml」且退出码 2；
- 优先级用例：同时给 `--book` 与 `BOOK_ROOT` 时以 `--book` 为准。

**风险**：`make.py` 的步骤表通过子进程调脚本，`--book` 必须传达到每个子进程，否则子步骤
退回兜底根。做法是选定后把书根写进子进程的环境变量（`BOOK_ROOT`），与步骤二的第 2 条
的优先级自洽：命令行显式给定者在父进程已解析完毕，子进程只读环境变量。
实现时在 `technical.md` §3.1 记录这条传播方式。

**回滚**：删除入口与相关用例；不涉及数据迁移。

## 步骤三：手稿的 edition 轴

**动作**：

1. `book.toml [editions]`：键为版本标识，值为显示名；**未声明即单版本**，目录形态不变。
   章节清单仍归书级（`[chapters]`），版本默认继承，需要时用 `[editions.<id>.chapters]`
   覆盖；图号与章号不因版本重排。
2. 声明后，各版本手稿放 `data/manuscript/<edition>/`（`[paths].manuscript` 仍指向
   `data/manuscript`，版本目录在它下面），`--edition` 选择；缺省版本写在
   `book.toml` 的顶层键 `default_edition`（**不放在 `[editions]` 表里**，否则与名为
   `default` 的版本冲突），未声明时取第一个键。
3. 派生状态与体量基线按版本分键：`state/<edition>/`、`baselines/<edition>/`（目录内的
   键与今天相同）；未声明 `[editions]` 时仍写 `state/`、`baselines/`（当前的位置）。
4. `content_volume.py` 的体量比对只与同版本基线比；跨版本比对必须显式给
   `--baseline <文件>`，不允许隐式回退。

**验收**：

- 未声明 `[editions]` 的书：`make.py check` 与产物路径不变；
- 声明两个版本的书：两版本的 `state/`、`baselines/` 互不覆盖，`content_volume` 不拿
  甲版本下限判乙版本（用例构造甲厚乙薄，断言乙仅在与自己基线比时通过）；
- `--edition` 指向未声明的版本时报错列出已声明版本。

**风险**：`data/manuscript/` 下出现子目录后，`front_matter()`/`back_matter()` 的 glob
会跨版本匹配。实现时必须把 glob 根限定到所选版本目录。这条是步骤三的主要陷阱。

**回滚**：删掉 `[editions]` 表即回到单版本形态；`state/<edition>/`、`baselines/<edition>/`
会作为残留目录留着，不影响单版本运行，确认无用后手工删除。

## 步骤四（条件成熟时）：工具链独立成包

**动作**：`src/python/` 抽成带 `pyproject.toml` 的包；默认配置随包分发；
`--book` 由「向上查找」改为必填；本仓只剩书目录与文档。

**前提**：步骤二的路径全部由注入得到，模块内不出现「从工具位置推导书根」；
否则换目录即失效。

**验收**：

- 把书目录单独复制到仓外，安装后的 `bookctl check` 能完整跑通，且结论与仓内运行
  同一本书时一致（不依赖仓内相对路径）；
  PDF/EPUB 交付验收只在装有 pandoc/playwright 的环境执行，缺工具时按既有约定跳过并报出
 跳过原因，不得静默通过；
- 仓内不再有「工具目录 → 书根」的推导（`_default_root()` 仅作为交互式兜底，且不再被
  任何门禁依赖）。

**回滚**：包化前后书目录形态不变，回退到仓内工具链即可。

## 四步之外：本仓自举与 CI

- **自举**：B 形态一启用，仓库自己也要变成「各书目录 + 并列的 shared 目录」。这需要一次
  `git mv` 与 `_default_root()` 兜底值调整，单独提交，验收是「门禁全绿、产物逐字不变」。
- **CI**：现有 `book.yml` 按单书跑；多书形态下按书各跑一次即可，不做跨书汇总。CI 的改造
  不在本计划内，但 B 形态不得让单书 job 变慢或变复杂。

## 顺序理由

步骤一是其余各步的公共前提（没有按书解析的配置，换书只能靠环境变量加重新导入）；
步骤二让「一次运行服务哪本书」可指定，并顺带把并发边界写清；步骤三才解决
「一本书多份手稿」。步骤四只换交付形态，不改变任何判定口径。
