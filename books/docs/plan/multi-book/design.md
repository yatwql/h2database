# 多书并行维护：设计与边界

> 定位：让同一套工具链服务于**多本书、每本书的多份手稿**，并说明哪些东西必须按书隔离、
> 哪些可以共享。实现细节在 `technical.md`，本文只说形态、约束与判定边界。
>
> 术语：**书根**指含 `data/book/book.toml` 的目录（当前就是 `books/`，多书形态下是
> 每个书目录）；**活动书**指 `_config.current()` 此刻指向的那一本；**版本**（edition）指
> 同一本书的一份手稿。书的目录标识沿用 `manuscript/archive.py::book_slug()` 的取值
> （合并名优先，否则由标题生成），不另造一套命名。
>
> 对应需求：`requirements.md` IR-10（一本书一份配置，书间不共享派生状态、基线与产物），
> 判据载体见 `testplan.md` §2.4。

## 1. 现状与缺口

配置已经能按书解析：`lib/_config.py` 的 `Config(root)` 读的是那一本书自己的文件，
模块级名字转发到「活动书」（`with _config.use(cfg):` 期间切换）。目录也已经是可配的：
`book.toml [paths]` 的 `state`、`baselines`、`manuscript`、`dist`、`tmp`、`book`、`templates`
各自可指到任意位置，`_log.log_dir()` 落在书根下。

按书选定的入口已经有了：`--book`（CLI、`make.py`、Web、TUI 各自接受）、`BOOK_ROOT`、
向上查找，优先级固定，缺 `book.toml` 时退出码 2 并给出试过的路径。因此**一本书不必和工具链
待在同一个检出里**——`--book` 指向任意目录即可，书目录与工具链之间没有文件复制。
手稿的版本轴也已落地（`[editions]`、按版本的状态与基线、重编号与引用改写）。

仍然缺的一件：**工具链自己的交付形态**。默认值（`base.json`、`style.json`、
`templates.toml`、`language/*.json`）目前是每本书各持一份，工具也只以仓内脚本的形式存在，
所以「给另一台机器上的另一本书用」仍要靠整份检出。步骤四把默认值收进包里、把 `bookctl`
变成安装后的命令，书目录里只留覆盖项。

门禁侧的耦合只有两处，且都不在门禁逻辑里：`_default_root()`（工具位置 → 书根）与
测试夹具的 `BOOK_ROOT`（同样由工具目录推导）。`check_architecture.py` 的
`PATH_LITERALS` 是**禁止表**——它禁止源码里出现 `books/`、`data/manuscript` 这类字面量，
正是「不硬编码路径」的执行者，不是耦合点。

## 2. 目标形态

### B — 一仓多书

```text
books/
  shared/                    # 工具链默认与共享资源
  <slug>/                    # 一本书：换书即整目录替换
    data/book/book.toml
    data/manuscript/
    data/config/{base,style}.json
    data/language/zh.json
    data/tmpl/templates.toml   # 默认取 shared/ 的那份，需要时才覆盖
    data/baselines/  data/state/
    dist/  logs/
  src/python/                # 工具链（B 阶段仍在仓内）
  docs/                      # 工程文档
```

### C — 工具链独立成包

书目录自包含并可单独复制；工具以命令安装（`bookctl --book <dir>`），共享默认随包分发
（`importlib.resources`），书里只留覆盖项。

## 3. 归属边界

| 归书（按书隔离） | 归共享 |
| --- | --- |
| `data/book/`（身份、章节表、案例流水线） | `src/python/`（工具链） |
| `data/manuscript/`、`dist/` | `data/tmpl/templates.toml`（可被本书覆盖） |
| `data/state/`、`data/baselines/`、`logs/` | `data/language/*.json` |
| 版本目录 `state/<edition>/`、`baselines/<edition>/` | — |
| `data/snapshots/`（本书用来比对的既往稿） | — |
| `data/config/base.json`、`style.json`（本书的取值） | `base.json` 的默认值（C 阶段随包分发） |

判据：**两本书各自有值、且互相比对没有意义的东西，必须按书隔离**。体积基线、术语表、
已知问题账本都属于此类——跨书比对只会产生假差异。

隔离由**书根**实现，不靠给文件加前缀：书根不同，`state/`、`baselines/`、`dist/`、`logs/`
自然不重叠。因此不引入「日志文件名带书标识」这类改法——它会在同一目录里把两本书的
日志混在一起，反而更难分辨。

## 4. 两个不同的「层」

容易混淆，先分清：

- **文件四层**（`folder.md` §3）：`data/book/book.toml`、`data/config/base.json`、
  `data/config/style.json`、`data/language/zh.json`。各层管什么、按什么顺序合并，**只在
  `technical.md` §3.1 定义**，本文不重复。
- **覆盖三层**（本文）：工具链默认 → 共享覆盖 → 本书覆盖。这是**多书形态**下的来源顺序，
  第 1 层目前不存在（默认值直接写在每本书的 `base.json` 里）。

第 1 层不是 B 阶段的前提：B 阶段每本书各自持有完整配置也能跑。它的价值只有一个——
让 C 阶段不必把散在各书里的默认值「收回来」。因此本文把它列为 C 阶段的准备工作，
而不是 B 的阻塞项。

## 5. 源目录怎么绑

源是这本书的输入：书读哪棵树写在 `data/book/book.toml [sources]`（`src_main`、`pom_root`、
`roots[]`、`version`），分析口径（`languages`、`suffixes`、`package_prefix`）留在
`data/config/base.json [sources]`，后者被前者按书覆盖。多书形态下每本书自带一份，隔离不需要额外机制。

**不做运行期切换源**：NFR-02 要求同一输入两次构建产物一致，体量下限又是对「某一版源 +
某一版稿」的评审结论。随手换源会让坐标断言、体量比对、术语摘录同时失去含义。要比两个源，
用归档与快照，不引入 `--source` 参数。

**一棵树不够时用多根**（一本书同时分析多个源）：

```json
"sources": {
  "roots": [
    {"label": "h2", "path": "../h2/src/main", "language": "java"},
    {"label": "client", "path": "../client/src", "language": "java"}
  ]
}
```

单根写法（`src_main`）继续有效，`source_tree('src_main')` 返回首根；`roots` 存在时按
`label` 解析。`source-inventory.json`、坐标报告与日志都要带 `label`，否则跨根的同名类无法区分。

兼容契约（不写清就会悄悄改类型）：

| 项 | 单根 | 多根 |
| --- | --- | --- |
| `source_tree('src_main')` | 该根路径 | 首根路径（保持不变） |
| `source_version()` | 字符串 | 字符串：所有根一致时返回该值，否则 `'mixed'` |
| `versions()['source']` | 字符串 | 映射 `label → 版本` |
| `label` | 隐含为 `main` | 必填且唯一，重复即 `ConfigError` |

多根书里给 `source_tree(key)` 传 `label` 才定位到具体根；传 `src_main` 一律等于首根。

**源指纹进基线**：体量基线写入 `source{label, version, digest}`。换源后指纹不匹配，
`content_volume.py` 报「基线来自另一个源，需复核」，不静默通过。

**导入期冻结是当前的真实障碍**：`source_refs.SOURCE_DIR`、`content_depth.source_root`、
`chapters.SOURCE_ROOT` 在模块导入时就把源根固定，`Config` 切书对它们无效。步骤二之前
必须把它们改成调用时读取——这是多书能力的前置，不是可选项。

## 6. 手稿的多版本轴

只有一本书要出第二份手稿时才引入，单版本时目录形态保持现状：

```text
data/manuscript/            # 单版本：维持现状，不建子目录
data/manuscript/<edition>/  # 多版本：每版本一个子目录，含该版本的章节与后件
```

`book.toml [editions]` 只声明**有哪些版本**与各自的显示名，不复制身份：

```toml
default_edition = "main"

[editions]
main = "主版本"
abridged = "删节版"
```

缺省版本写在顶层 `default_edition`，不放进 `[editions]` 表——否则与名为 `default`
的版本冲突。

**章节清单归书，版本可覆盖**：`[chapters]` 仍是书级的（阅读顺序、编号、包归属），
版本默认继承；只有当某版本确实有不同章节时，才在自己的表里覆盖：

```toml
[editions.abridged.chapters]
files = ["cover.md", "ch1-2-architecture.md"]
```

**章号重编号，图号不重排**：`audit/structure.py` 要求 H1 章号是 `1..N` 连续，删节版若
沿用原编号会留下空洞，判定必红。因此版本按保留章节重编号（`1..N`），并把「原章号 → 新章号」
记录在该版本的派生状态里，供跨版本对照；图号在各自章节内不变，避免同一张图叫两个号。

**产物按版本命名**：`merged_name` 是书级的，多版本直接沿用会互相覆盖。缺省命名为
`<merged_name>-<edition>`，需要固定名字时在 `[editions.<id>].merged_name` 显式给出；
`dist/` 下各版本产物并列；PDF 与 EPUB 的校验脚本都按这一命名查找产物。

派生状态与体量基线跟着版本分键：`state/<edition>/`、`baselines/<edition>/`，
目录内的键与当前一致。否则第二份手稿一进，`content_volume.py` 会拿甲版本的下限判乙版本。
`quality-model.md` §4「只比一份、不做加权」的原则不变：每个版本仍然只与**自己那一份**
基线比，不引入跨版本平均。

### 版本的目录派生

多版本不是「多一个子目录」那么简单，每类文件都要回答「按书还是按版本」：

| 位置 | 单版本（当前） | 多版本 |
| --- | --- | --- |
| 派生状态 | `[paths].state` | `[paths].state/<edition>/`，内含 `renumber.json`（原章号→新章号） |
| 体量基线 | `[paths].baselines` | `[paths].baselines/<edition>/` |
| 产物 | `[paths].dist` | 目录不变；文件名带版本（见下） |
| 日志 | `logging.dir` | 不变——按书，不按版本 |
| 数据归档 | `data/archive/<slug>/<date>/` | `<slug>-<edition>/<date>/` |
| 快照 | 账本记体积 | 账本同时记版本标识 |

判据是「这条信息属于哪一层」：状态与基线是**版本级事实**，两版混在一起就必错；日志是
**进程级排障信息**，按版本拆开只会让同一次运行的日志散在两地；归档与快照要能回答
「这是哪一版手稿」，所以版本标识进目录名或清单。

**章号映射落盘**：重编号生成 `renumber.json`（`{"原章号": 新章号}`），跨版本对照与引用
改写都以它为准；没有这份文件，跨版本比较就只能靠猜。

## 7. 并发与「活动书」

`use()` 改的是进程级活动书，因此：

- **一次运行服务的是一本书**：`--book` 选定的书在整次运行内不变；命令行工具、`make.py`
  的每个步骤都满足这一点。
- **并发场景不共享活动书**：Web 控制台（多线程）一个进程只服务一本书，启动时选定；
  若将来要在一个进程里服务多本，处理函数必须接收显式的 `Config` 实例，而不是依赖
  `current()`。
- 测试里可以安全地连续切换（单线程、串行），已有用例覆盖嵌套与异常还原。

## 8. 三个渠道怎么选书与选版本

三个入口共享同一份 `ACTIONS` 与设置（IR-06），选书只改变**活动书**，不改变动作集合。
但三者的交互形态不同，做法也不同：

| 渠道 | 选书方式 | 约束 |
| --- | --- | --- |
| CLI（`bookctl` / `app/cli.py`） | 全局 `--book` / `--edition`，优先级同 §10 | 一次运行一本书；缺书即退出码 2 并指路 |
| `make.py`（CI 与脚本） | 同上，父进程解析后写进子进程环境变量 | 每个步骤子进程都拿到同一个书与版本 |
| Web（`app/web.py`） | 顶部「书 / 版本」选择器，选择随每次动作请求发出；启动参数只定默认值 | 动作在**子进程**里跑，选择随环境变量传下去；同进程内的少量读取（状态、设置）包在 `use()` 上下文里 |
| TUI（`app/tui.py`） | 启动参数同上；另有二级「书籍」屏可切换 | 单线程，可安全切换；切换前要求无进行中的动作，切换后清空结果区与状态摘要 |

**为什么 Web 不需要加锁**：`core/actions.py` 的每个动作都以子进程执行（`make.py` 与各脚本），
选中的书通过 `BOOK_ROOT` / `BOOK_EDITION` 传进子进程，进程之间天然不共享状态。同进程内
只有 `status`、`settings` 这类轻动作会直接读配置，它们各自包在 `use(Config(book))` 上下文里，
执行完即还原——线程之间看到的活动书只在各自请求的上下文内存在。TUI 同理：它是单线程，
但动作同样走子进程，切换书只是换一个传给动作的参数。

**TUI 的「书籍」屏**：候选来自向上查找命中的书，加上同仓 `books/` 下并列的兄弟书；
只列**能读到 `data/book/book.toml` 的目录**。屏头显示当前活动书的书名、书根与版本
（声明了 `[editions]` 时一并显示当前版本）。切换后必须清屏：上一本书的结果与门禁
摘要对当前书没有意义，留着只会误读。

**三个渠道的一致性**：同一动作、同一本书、同一版本，三个入口给出的结论必须相同；
`--book` 只影响「读哪本」，不得改变任何动作的行为或输出格式。

### 界面上怎么选书

两条渠道的界面形态不同，但遵循同一套习惯：**候选可见、当前选中可见、切换即时生效、
切换后不留上一本书的结果**。

**TUI**：沿用 `DESIGN-TUI.md` 的七段分区，不新增模式。

- 对象行（第三段）已经显示书名与版本，多书时补上**书根**；单书时保持现状，不制造噪声。
- 「切换书籍」放在「配置与状态」二级屏里——按该文档的分级标准，选书是偶尔的动作，
  不该占主菜单的数字键。
- 屏幕内容：候选列表（序号、书名、书根、版本），当前项以 `●` 标记；数字键直选，
  `0` 返回，与既有键位语义一致。
- 切换守卫：有动作正在执行时忽略切换并提示；切换成功后清空结果区与状态摘要，
  因为上一本书的四段反馈对当前书没有意义。
- 只有一本书可发现时，该屏显示「仅一本」并不列出候选，避免让人以为还有别的可选。

**Web**：仍是单页按钮式界面，不引入前端框架。

- 页面顶部加一行「书 / 版本」两个下拉框，默认值来自启动参数；切换后无需刷新即可继续点动作。
- 候选来自 `/api/books`（与 TUI 同一份发现逻辑：`[paths].library` 目录下的书 + 向上查找命中的书；
  `library` 缺省为本书的父目录）。
- 每次动作请求带上选中的书与版本，服务端以子进程环境变量传入；页面把「当前书 · 版本」显示在标题旁。
- 找不到书或书被移走时，页面给出可读错误（列出试过的路径），不显示堆栈。

**都不做的事**：不记忆上次选择（`--book` / `BOOK_ROOT` / 向上查找已经足够可预测，
隐式记忆反而让「为什么跑的是那本」难以解释）；不做书与书的对比视图；不在界面上新建书
（建书是 `scaffold` 的职责）。

## 9. 非功能需求怎么适用

- **体积预算（NFR-06）按书算**：每本书的 PDF/EPUB 各自受上限约束，不做跨书合计。
- **环境唯一（NFR-03）不变**：多书共用同一个隔离环境，不为某本书单独装依赖。
- **可移植（NFR-09）要覆盖新行为**：向上查找必须走到文件系统根为止、路径比较用
  `realpath`、在大小写不敏感的文件系统上按不敏感比较，且不依赖盘符书写。
- **无过程痕迹（NFR-12）不变**：多书形态不引入「上一版书」这类过程产物。
- **不做跨书汇总检查**：`make.py check` 一次只判一本书；要多书一起判，按书写循环调。

## 10. 与语言包计划的关系

两件事容易混：

- **版本（edition）**是同一本书的**内容**不同（删节、增补、不同年份）；
- **语言（language）**是同一份内容的**资源**不同（骨架名、提示语、图注前缀）。

语言资源由语言包计划负责（`docs/plan/language-pack/`；`data/language/<code>.json`
与判据取值改造），本计划不碰它的
判定口径，只约定组合时的命名：同时有版本与语言时，产物名再加语言后缀
（`<merged_name>-<edition>-<lang>`），否则 `BOOK_LANGUAGE` 一变就会覆盖上一份产物。
单版本、单语言时行为与当前一致。

## 11. 初始化顺序（实施时的硬约束）

`Config()` 目前在 `lib/_config` 导入时就构造一次（`_DEFAULT`），那一刻 `--book` 还没被解析：
书根不存在就会在 import 阶段失败，入口没有机会报出可读错误。因此步骤二必须同时做两件事：

1. 入口先解析参数、选定书根，再构造 `Config`。入口有两个：`app/cli.py`（经 `scripts/bookctl`
   包装）与 `make.py`——**两者都要接受 `--book` 与 `--edition`**，否则 CI 走 `make.py` 时
   选书无处可传；
2. 模块级 `_DEFAULT` 惰性构造：首次 `current()` 时才构造，`use()` 之后不回头读它。

惰性构造仍走同一套优先级，只是没有 `--book` 这一档：环境变量 `BOOK_ROOT` → 向上查找
→ 工具链所在 checkout。找不到任何书根时，错误在**首次使用配置的时刻**抛出，而不是导入时——
调用方因此能捕获并给出一句可读提示，测试也能构造「没有书」的场景。

**配套规则：消费方不得在导入期读配置。** `_config` 惰性化本身不够——`SOURCE_ROOT =
_config.source_tree('src_main')` 这样的模块级赋值会在**导入该模块时**触发构造，错误时序又回到
导入期，切书也依然不生效。规则是：配置只在函数体内读取；已知的三处（`source_refs`、
`content_depth`、`chapters`）在步骤二的前置里改掉，并由 `check_architecture.py` 新增一条
机检（不得在模块顶层对 `_config` 取值）防复发。这条机检按「登记存量、只挡新增」落地：
先以三处已知位置为白名单，前置完成后白名单应为空——白名单不清空，说明解冻没做干净。

这条不解决，`--book` 只能在一部分调用路径上生效，另一部分仍在导入期按兜底根读盘。

## 12. 文档改动面

多书能力落地时要同步的位置（缺一处就会出现两套说法）：

| 文档 | 要改什么 |
| --- | --- |
| `technical.md` §3.1 | `Config` 的构造时机、书根来源与优先级 |
| `folder.md` §1 §3 | 多书形态的目录树与归属表 |
| `testplan.md` §2.2 §2.4 | 选书相关判据与 IR-10/IR-11 行 |
| `quality-model.md` §4 | 每版本只比自己那份基线 |
| `requirements.md` | IR-10/IR-11 的措辞与组合边界 |

## 13. 版本与多书下的门禁口径

门禁大多按「章号的字面值」判定。版本轴一旦重编号，这些判据要么跟着版本走，要么明确
不适用——不能靠运气：

| 门禁 | 现在的判定 | 版本下的口径 |
| --- | --- | --- |
| `structure.py` | H1 章号必须是 `1..N` 连续 | 按版本自己的编号判（重编号后仍连续） |
| `crossrefs.py` | `详见第X章《…》` 必须命中真实 H1 | 重编号时**同步改写正文引用**，判据不变 |
| `index_xrefs.py` | 子条目章号 ∈ 1-12（硬编码） | 按该版本的章号集判定；1-12 的硬编码在步骤三清除 |
| 术语表 | 每条有章号指引 | 指引随重编号改写，判据不变 |
| `content_depth.py` | 前向引用按章号键控 | 基线按版本分开（`baselines/<edition>/`），键用该版本自己的编号 |
| 封面与 manifest | 记录版本号 | 追加版本标识与语言标识，避免两份手稿的产物互相覆盖 |
| `check_runner.py` | 按改动文件所属目录选门禁 | 分档跟随**活动书**：别的书的改动映射到独立域并忽略，不得当成 infra 触发全量 |

多书不改变任何判定口径：每本书各自有 `book.toml` 与编号，门禁读的都是活动书的配置。


## 13. 书目发现与产物的分层

四个决定，前三个已落地，第四个是取舍：

1. **书目目录可配**：`[paths].library` 指定「其他书放在哪」（缺省＝本书父目录）；
   `candidate_books()` 只认该目录下带配置的目录。
2. **两种配置文件布局都认**：`<书根>/data/book/book.toml`（标准）与 `<书根>/book.toml`
   （扁平）。一个书目目录因此可以同时装「根上的一本」与「子目录里的多本」。
3. **选择界面同时显示书名与目录名**：TUI 的「书籍」屏与 Web 的 `/api/books` 都带目录名，
   两本同名书不会混。
4. **`dist`/`manuscript` 不按书再分层**：每本书本身就是独立书根，产物与手稿已经在各自根下
   （`<书根>/dist`、`<书根>/data/manuscript`）。只有当多本书共享一个书根时才需要再嵌套一层，
   而那会引入「同一 `[paths]` 下按书切分」的新语义——本设计不引入，理由是它让每一条路径都
   多一个变量，而收益只有「少一个目录」。

## 14. 非目标

- **不做多书合一构建**：一本书一份产物；多本合并成一个 PDF/EPUB 不在范围内
  （`technical.md` §10 已登记）。
- **不做跨书一致性检查**：术语、图号、引用只在本书内判定。
- **快照仍按书存放、仍只读**：`data/snapshots/` 属于某一本书，内容是「这本书比对用的既往稿」，
  来源可以是该书自己的历史版本，也可以人工放一份别的书的稿子（NFR-07 允许，且快照不参与
  构建与检查）。工具不会自动跨书生成快照——需要横向比较时人工取用，避免快照目录变成
  无人维护的多书混合区。
- **不改判定口径**：选书与分层只决定「读哪个文件、写到哪里」，不改变任何阈值语义。
- **不做旧布局兼容**：`lib/_config.py` 只认 `data/book/book.toml`。仍把 `book.toml` 放在
  旧位置的书，报错时直接给出期望路径，不自动回退——猜位置比报错更难排查。

## 15. 迁移路径

四步，顺序不可换：步骤一只提供「按书解析」的能力，步骤二才让人指定跑哪本书，
步骤三解决同一本书的多份手稿，步骤四只换工具链的交付形态。每步的动作、验收与回滚
写在 `plan.md`，这里只记顺序与等价条件：

| 步骤 | 内容 | 合并前必须成立 |
| --- | --- | --- |
| 一 | 配置按书解析 | 调用形式与取值不变；渲染文本哈希不变 |
| 二 | `--book` 入口 + 向上查找 | 不带 `--book` 时产物、日志位置、门禁结论与当前逐字一致 |
| 三 | 手稿 edition 轴 | 未声明 `[editions]` 的书完全不受影响；重编号只在声明版本时发生 |
| 四 | 工具链独立成包 | 仓外书目录上 `bookctl check` 的结论与仓内一致 |

四步都不产生数据迁移，因此都能单独撤销：步骤二去掉入口、步骤三删 `[editions]` 表、
步骤四回退到仓内工具链。

**自举不在四步内，但会被触发**：一旦本仓按 B 形态组织，仓库自己也要变成「各书目录 + 并列的 shared 目录」，
需要一次 `git mv` 与 `_default_root()` 兜底值的调整。这一步单独做、
单独提交，结论必须仍是「门禁全绿、产物不变」。

## 16. 门禁影响

- `_default_root()` 只作兜底：给了 `--book` 时不参与解析，也不被任何门禁依赖；
- 测试夹具把「工具目录」与「书目录」当两个独立概念：夹具书根不从工具目录推导；
- 已有用例继续守住配置对象本身（两本书互不串值、切换失败也还原、缺 `book.toml` 仍报
  `ConfigError`）；`--book` 的入口行为由步骤二的用例覆盖，不在这里重复。
