# LLM 契约起草与自评审：迭代设计

> **状态：未开工**——本文是设计文本；LLM 调用面与契约均未改动。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**让模型在契约内起草、再自查**——输入是事实与依据，输出必须过判据。

---

## 1. 问题

现在 LLM 只起草章节导读与小节小结，输入是包摘要，输出没有可核验的约束：可以编造数字、可以写
没有坐标的断言。于是「模型写得越多，质量风险越大」，无法用在真正需要写作量的地方
（学习目标、误区、代码标注解释、术语定义）。

## 2. 目标与非目标

**目标**：任何 LLM 产出的段落都带「输入依据 + 输出契约 + 事后判据」三件套；同一书同一配置重跑可复现。

**非目标**：不做全书自动成稿（正文仍由人定稿）；不追求模型选择的统一（走现有 provider 配置）。

**硬约束**：模型不得引入事实块里没有的数字；不得新增或删除代码标注编号；每个强断言必须带依据。

## 3. 契约与判据

| 任务 | 输入 | 契约（输出必须满足） | 判据 |
| --- | --- | --- | --- |
| 学习目标 / 要点回顾 | 本章事实块 + 小节标题 | 3–5 条，每条 ≤1 行，关键词与小结呼应 | `learning_goals` / `key_points` |
| 常见误区 | `failure` + `invariants` 块 | 「误区 + 为什么」两段，误区带坐标 | `pitfalls` + `claims` |
| 代码标注解释 | 代码块 + 标注点行号 | 每编号一句，不增删编号 | `callout` |
| 术语定义 | 术语表候选 + 出现上下文 | 一句定义 + 章节指引，中英对照 | 术语表判据 |
| 自评审（不进正文） | 已定稿正文 + 事实块 | 输出「无依据断言 / 该提示未提示 / 含糊句」清单 | 人工采纳 |

## 4. 风险

- 契约过严会让模型写出模板腔；缓解：契约只管要素与依据，不管句式，文风判据已有 `style.py`。
- 复现性依赖模型版本；缓解：调用台账记录 prompt 摘要、响应哈希与配置指纹。
