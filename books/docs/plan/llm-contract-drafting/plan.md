# LLM 契约起草与自评审：实施计划

> **状态：未开工**——本文是计划文本；LLM 调用面与契约均未改动。
>
> 软件：bookwright — 源码分析成书工具 v0.2-dev
> 版本：v0.2-dev
> 定位：**动作与验收**——先立台账与契约，再逐个任务放开。设计看同目录 `design.md`。

---

## 1. 前提

- 现有调用面只能起草导读/小结（`chapters.py --llm`），provider 与场景已在配置里。
- 「依据」判据由依据化迭代提供：没有 `claims` 判据，起草契约就无从验收。

## 2. 阶段

### 阶段 1：台账与契约骨架

1. 每次调用记录：任务名、prompt 摘要、响应哈希、模型与配置指纹，落 `data/state/`（gitignore）。
2. 契约以配置声明：每个任务允许的输入块、输出形态（条目数、字数上限）、必须携带的依据类型。

**通过条件**：同一输入重跑得到相同台账结构；契约缺失时任务拒绝执行并报告。

### 阶段 2：低风险任务放开

1. 学习目标、要点回顾：输入事实块，输出条目；由判据验收。
2. 代码标注解释：编号由脚本分配，模型只写解释。

**通过条件**：两项任务产出的段落全部过判据；人工抽查 3 章无明显编造。

### 阶段 3：误区与自评审

1. 常见误区：以 `failure` / `invariants` 为候选，模型写「为什么」，坐标必须可解析。
2. 自评审任务：对定稿正文输出结构化清单，进报告不进正文；人决定采纳。

**通过条件**：误区条目全部带坐标；自评审报告能在本书里指出至少 3 处真实问题（人工确认）。

## 3. 命令

```bash
books/.venv/bin/python books/src/python/ingest/chapters.py --llm --only <章文件名>
books/.venv/bin/python books/src/python/make.py check --only claims
```

## 4. 回退

每个任务独立开关（配置里一行为准）；关掉即回到「只起草导读/小结」的现状。
