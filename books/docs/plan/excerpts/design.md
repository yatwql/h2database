# 源码摘录优先：迭代设计

> **状态：阶段 1 已落地**——范围头、省略标记与子序列校验已进判据；生成器与铺开待做。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**让「贴源码」成为标准动作**——每段实现论述都先给可核验的摘录，而不是手绘图与复述。

---

## 1. 问题

本书 40,121 行里 72.8% 是围栏块，其中只有 111 块是真 Java 源码，978 块是 `text`（手绘 ASCII 图、
自拟 trace）。这些块**不可核验、不可维护**，而且是体积的主要来源。反过来，脚本最擅长的
「按坐标取源码并校验」几乎没用上：全书只有 232 处坐标、43 个围栏前有 `文件:行号`。

## 2. 目标与非目标

**目标**：给摘录一个标准形态——围栏首行是 `// 文件:起-止`，正文来自该范围，允许用 `// ...` 省略；
判据按「顺序子序列」校验，改一行代码就红。配一个生成器，作者不再手抄。
**非目标**：不强制每段都有摘录（叙述、取舍、总结不需要）；不改图（图是另一个迭代的事）。

## 3. 形态与判据

```java
// TransactionMap.java:527-533
Snapshot<K,VersionedValue<V>> getSnapshot() {
    return snapshot == null ? createSnapshot() : snapshot;
}
// ...
```

| 规则 | 判定 |
| --- | --- |
| 无省略 | 正文逐行等于该范围，行数一致 |
| 有 `// ...` | 正文是范围内的**顺序子序列**，逐行必须在源码里出现 |
| 行尾注释 | 允许在源码行后追加 `// 说明`（本书体例） |
| 省略未标注 | 视为漂移——跳过的行必须显式标出来 |

## 4. 取舍

- **子序列而非严格相等**：允许「类 + 八个字段」这类摘录跳过 javadoc，否则作者只能整段粘贴。
- **行尾注释允许**：这是本书解释代码的方式，判据只保护「代码本身没被改」。
- **判据先于生成器**：先让存量暴露（本次一次抓出 16 处引用错行的摘录），再谈铺开。
