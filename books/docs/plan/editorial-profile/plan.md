# 编辑风格档：实施计划

> **状态：未开工**——本文是计划文本；手稿与判据均未改动。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**动作与验收**——先量化、再补内容、最后调下限。设计看同目录 `design.md`。

---

## 1. 前提

- 语言包已能承载标签词表（`data/language/<code>.json`）；`[sections]` 已强制四个必备段落。
- 判据只读手稿与配置，不改产物；新增判据都进 `make.py check` 的 verify 组。

## 2. 阶段

### 阶段 1：配置与量化（只读数）

1. 新增书级配置（`data/book/` 下）：`[profile] name` + 每元素的门槛；三档预设作为默认表写在
   `lib/` 里，书可以逐项覆盖。
2. 新增三个只读判据：`learning_goals`、`pitfalls`、`table_density`。先用它们量出本书的现状
   （预期：学习目标 3/14、常见误区 0、表格密度 ≈0.08/千行），作为基线记录。

**通过条件**：三个判据在本书上能给出数字，且对「本档未启用」的元素不报错。

### 阶段 2：补内容（先本书，再回灌模板）

1. 按判据缺口补：每章学习目标与要点回顾条目化、常见误区（来源是分析层的失败路径与不变量）、
   对比类论述改表格（与既有表格化迭代合并推进）。
2. 把补出来的形态回灌到 `chapters.py` 的骨架模板与 LLM 起草契约，使新书默认具备。

**通过条件**：本书三个判据全绿；`make.py check` 与 `deliver` 不变红。

### 阶段 3：其余元素

1. 代码清单编号（渲染期统一编号 + 引用可达判据）、术语中英对照、提示类区块词表与下限。

**通过条件**：每个新判据都有能红的用例；换一种风格档时只改配置即可通过。

## 3. 命令

```bash
books/.venv/bin/python books/src/python/make.py check --only <新判据名>
books/.venv/bin/python books/src/python/make.py build
```

## 4. 回退

判据与配置分开提交：判据只读，关掉该项即恢复现状；配置项默认关闭，存量书不受影响。
