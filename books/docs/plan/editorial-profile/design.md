# 编辑风格档：迭代设计

> **状态：未开工**——本文是设计文本；手稿与判据均未改动。
>
> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 定位：**把「出版社风格」变成可配置的元素集合**——哪些要素必须有、叫什么、下限多少。
> 不写动作与排期（看同目录 `plan.md`）。

---

## 1. 问题

优秀技术书的要素是稳定的（学习目标、前置知识、要点回顾、常见误区、代码清单编号、术语中英对照、
图表并重、提示类区块），但各家的**取舍与密度**不同：手册型少提示、实战型多提示、教程型要学习目标。
现在这些要素只有四项被 `book.toml [sections]` 强制，其余全靠作者自觉，于是本书出现
「提示类全书 2 条、代码标注 0 处、表格 3 处」这类结构性缺口，而门禁判不出来。

## 2. 目标与非目标

**目标**：一本新书选定风格档后，元素集合与下限由配置取代自觉；判据只读配置，换档不改脚本。

**非目标**：不强制某一出版社的写法（不做「必须像 X 社」的判据）；不判文字好坏（那仍由人）；
不替代 `[sections]` 的必备段落（它是必需项，这里是密度与形态）。

**硬约束**：所有标签取自语言包；门槛值取自配置；任何元素缺省时判据不报错，只报告「本档未启用」。

## 3. 元素与判据

| 元素 | 形态 | 判据 |
| --- | --- | --- |
| 学习目标 | 每章 3–5 条，与小结一一对应 | 条目数下限；每条在学习目标里出现的关键词至少一条出现在小结 |
| 前置知识 | 一段，可列 | 存在性（已由 `[sections]` 覆盖） |
| 要点回顾 | 条目化小结 4–6 条 | 条目数下限；条目不得是整段 |
| 常见误区 | 每章 1–3 条，「误区 + 为什么」并列 | 条目数下限；每条两段结构 |
| 实战链路 | 全书 ≥1 条带源码坐标的端到端路径 | 坐标可达（复用 `source_refs`） |
| 代码清单编号 | `清单 N-M`，正文引用之 | 编号唯一连续；每个清单被引用至少一次 |
| 术语中英对照 | 首次出现处给英文 | 与术语表别名对齐 |
| 图表并重 | 每千行 ≥1.5 张表 | 密度下限 |
| 提示类区块 | Note/Tip/Warning 形态 | 词表合法 + 每章下限 |

## 4. 风险

- 密度下限会激励「为凑数加提示」；缓解：判据同时要求提示块内至少一句带源码坐标或事实引用。
- 风格档不宜过多：先三档（手册 / 教程 / 实战），自定义档只在确有差异时新增。
