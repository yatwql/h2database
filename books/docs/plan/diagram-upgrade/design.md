# 图示升级迭代设计：ASCII → 结构化图

> 软件：bookwright — 源码分析成书工具 v0.1
> 版本：v0.2
> 定位：**图示升级的设计说明**——为什么升级、升级到什么形态、四种交付格式各自怎么处理、
> 哪些门禁必须跟着改。不写排期与逐项动作（看同目录 `plan.md`），不重复全书架构
> （看 `technical.md`）。追踪编号只在 `plan.md` 的计划项里。

---

## 0. 术语

| 术语 | 在此处的含义 |
| --- | --- |
| 图注行 | 手稿里 `**图 N-M: 标题**` 那一行，图号与标题的唯一来源 |
| 图源块 | 图注下方的图本体：ASCII 围栏或图片引用 |
| 图片型图源 | 以 `![alt](assets/diagrams/*.svg)` 引用的图源块 |
| 内联资产 | 构建期把 SVG 读成 `data:image/svg+xml;base64,…` 写进 HTML 的那份字节 |
| 图片引用数 | 合并稿里图片型图源的个数，是所有新判据的分母 |

## 1. 目标与非目标

**目标**：让少数复杂流程图摆脱 `ascii_max_cols` 的宽度约束与等宽字体的可读性上限，
在 HTML / PDF / EPUB 三个出口上都清晰可读，同时不破坏"图号唯一连续、图注可解析、
渲染确定"这三条既有契约。

**非目标**：不做通用绘图工具、不引入在线渲染服务、不把既有 ASCII 图整体重画、
不让图片成为门禁判据之外的"看不见的黑箱"。

**硬约束**：手稿仍是唯一可编辑源；合并稿与三个产物都必须可从手稿完整重建；
任何一张图都不允许"渲染时静默消失"。

---

## 2. 现状事实（升级前）

图在本书里由三样东西构成，缺一不可：

| 层 | 形态 | 判据所在 |
| --- | --- | --- |
| 图注 | 文本行 `**图 N-M: 标题**`（附录为 `**图 A-M:**`） | `structure.py` 的编号唯一/连续、`figures.py` 的图数与"如图 X-Y 所示"引用、`captions.py` 的词表与长度、`figure_clusters.py` 的桥接句 |
| 图源 | ` ``` ` 围栏内的等宽字符画 | `diagrams.py` 的宽度预算（`ascii_max_cols`）与边框混用检查 |
| 出口 | 合并 md → HTML → PDF / EPUB | `merge.py`、`to_html.py`、`to_pdf.py`、`to_epub.py`、`verify_pdf.py`、`verify_epub.py` |

关键事实：**图号与图注完全靠文本判据**，与图源形态无关；因此升级只动"图源"和"出口"两层。

---

## 3. 图的三层模型（升级后的契约）

1. **图注层不变**：仍然是 `**图 N-M: 标题**` 这一行，位于图源之前（版面自上而下：图注、空行、图源）。
   所有既有判据继续只看它。
2. **图源层新增一种形态**：结构化图以 SVG 资产存在，正文用一行引用指向它，
   并保留同一条图注。ASCII 围栏图继续合法，两种形态并存。
3. **出口层各自负责"如何把资产变成可读的图"**：HTML 内联、PDF 随 HTML 走、EPUB 由
   pandoc 打包。出口层的差异只允许出现在渲染细节，不允许改变图号与可访问性。

图源引用采用图片语法，位置与该图注相邻，并且**图注在上、图源在下**，与现有 ASCII 图
（`**图 6-1: …**` 在前、围栏在后）保持一致，改形态不改版式：

```markdown
**图 7-1: SQL 执行与优化的数据流**

![图 7-1 SQL 执行与优化的数据流](assets/diagrams/fig-7-1.svg)
```

图注行与图片 `alt` 文本必须一致（同一条图号与标题），`alt` 是图片读不出来时的兵底。

---

## 4. 为什么是 SVG（而不是 PNG / Mermaid / 在线渲染）

| 候选 | 取舍 |
| --- | --- |
| SVG | 文本格式，可 diff、可审阅、可版本化；矢量，PDF/EPUB 清晰；`verify_pdf` 的字体判据可覆盖（文本可转路径规避字体缺失） |
| PNG | 二进制不可审阅，需双倍资产（EPUB 与 PDF 可能要求不同分辨率），仓库膨胀，审阅成本高于收益 |
| Mermaid | 需要渲染时执行 JS（Chromium 之外还要 pandoc 侧支持），渲染不确定，且把"图的语义"交给运行时 |
| 在线渲染 | 违反离线与确定性约束，构建依赖外网 |

结论：**SVG 为唯一新增形态**。图内文字默认只用与字体无关的标签（英文、数字、代码符号）；
确实需要中文时把文字转成路径（text→path，由作图方在导出时完成），不把字体子集化引入构建链。
判据上由以两道保险兑现：制作规范（非中文或转路径）+ `verify_pdf.py` 的图片数判据（见 §6）。

## 5. 四种格式的处理

### 5.1 md（手稿源）

- 图源块由 ` ``` ` 围栏改为图片引用；图注行保持原样。
- 引用写成相对路径（`assets/diagrams/fig-7-1.svg`），**不得以 `/` 开头**：`links.py` 会把以 `/`
  开头的目标当成“手稿根相对”，等于同时允许两套写法。
- 图注后空一行再放图片，且图片与图注必须落在同一小节（同一个 H2）内；前者让 GitHub 预览
  与渲染器一致，后者让图簇与桥接句的判据仍能就近认出它们。
- **行数下降要处理体量基线**：一张 ASCII 图占几十行，换成图片后该章 md 行数会明显下降，
  可能低于 `content_volume` 的逐章下限。因此替换与基线必须同一变更：按 `content-quality-policy.md` §4
  的流程重记基线（需具名评审人与提交），或补足同等信息量的文字；不得让其静默变红。
- **路径基准以文件为原点**：`links.py` 把相对目标按“引用所在文件的目录”解析
  （`os.path.dirname(path)`），所以资产放在手稿目录内、引用写 `assets/diagrams/fig-<章>-<序号>.svg`；
  配置键 `[paths] diagrams` 的默认值即该子目录，`_config` 提供访问器，脚本不写死路径（C-03）。
  资产不放在手稿目录外：那样每张图都得写 `../assets/…`，既易错又让“图片引用数”无法在章内自洽。
- 适用范围：全部手稿文件（章节、附录、前件与后件），不只章节。
- 拆分规则：章节图号不带字母后缀（字母后缀只属附录），一张图太大就**新增图号**，
  不写 `图 7-1a`，否则图号唯一性与 `figures.py` 的引用统计会出现两种口径。
- 资产目录建时放一个 `README.md` 说明命名与图号对应规则（避免空目录不入库、后人命名漂移）。
- 资产进版本库；内容为纯文本 SVG，禁止嵌入位图与外部引用（不得有 `<image href="http…">`）。
- `diagrams.py` 只审 ASCII 围栏，图片型图源必须由该门禁**显式声明不受理**并在输出里计数，
  否则这类图会静默脱离所有图源判据。
- 资产目录沿用仓库已有约定（`[paths] cover_image` 已指向一个资产目录），
  图目录由 `[paths] diagrams` 给出，由 `_config` 提供访问器——路径不得写死在脚本里（C-03）。
- 资产缺失分两级：`links.py` 作为门禁报红（缺文件 / 大小写不符 / 不可解析）；`to_html.py`
  构建时找不到资产直接失败并点名文件，不静默降级为文字。
- `content_volume.py` 只统计章节 md 文件，资产不计入体积基线；因此图片不会让体量门禁
  “变薄”，也不会因资产增删而误报。

### 5.2 HTML

- `to_html.py` 当前**没有图片语法**：`![alt](src)` 会被当成行内链接渲染成 `!<a>`，必须新增
  解析分支，输出 `<figure class="diagram"><img src="…" alt="…"></figure>`。
- **正则顺序是硬要求**：现有的 `\[([^\]]+)\]\(([^)]+)\)` 在前，会把图片语法先吃掉；
  图片分支必须在该规则之前处理（或改成负向前瞻 `(?<!!)`），否则一上图就是坏 HTML。
- **alt 字符集**：alt 只用中英文、数字、空格与连字符，不得出现 `(`、`)`、`[`、`]`，
  否则解析会被括号截断。
- **路径编码**：资产路径只用 ASCII 与连字符；若图目录含空格或非 ASCII，引用必须 URL 编码，
  否则 EPUB 里的 href 与 `links.py` 的解析会不一致。
- 构建期把 SVG 内联为 `data:image/svg+xml;base64,…`：产物保持单文件、`file://` 可开、
  `print_pdf.py` 复用同一份 HTML，且不受资产路径影响。
- 新增 CSS：`img{max-width:100%;height:auto}`、`figure.diagram{margin:1em 0}`，打印时
  `figure{page-break-inside:avoid}`。
- 体积代价可测但不新增阈值键：构建输出报告内联资产数量与字节数，体积正面以既有
  `pdf_max_mb` / `epub_max_mb` 与人工核查为限（仓库还没有 HTML 体积阈值键，新增一个键
  需要同步 `technical.md` §3.2，本项不引入）。

### 5.3 PDF

- 走现有链路（HTML → Chromium），图片随 HTML 走，无需新增渲染代码。`print_pdf.py` 读的也是
  `merged_html()`，所以 data URI 内联对它同样生效，两个 PDF 分支不需要各自处理资产路径。
- 两个必须处理的风险：
  1. **CJK 字体缺失**：Chromium 在无 Noto CJK 的机器上会把中文标签画成缺字，
     而 `verify_pdf` 只判“字体是否嵌入”，仍会 PASS。对策：作图时 text→path，或标签只用
     英文/数字；判据用 §6 的统一口径（图片对象数 == 图片引用数）。
  2. **页边界切断**：图表落在分页处会被腰斩。现有打印 CSS 已有 `pre, table { page-break-inside: avoid; }`，
     把 `figure` 加进同一条规则即可，不需要新规则。
- 体积受 `pdf_max_mb` 约束；内联矢量图会增加页数与字节，需要在上限内验证。

### 5.4 EPUB

- pandoc 现有调用形如 `--to=epub3 --split-level=1 --toc`，**没有 `--resource-path`**：
  相对路径图片会被 pandoc 静默丢弃。必须补 `--resource-path=<手稿目录>:<dist>`（资产在手稿目录内，
  一个前缀就够；若后续移出手稿目录，就再补资产目录，顺序不敏感）。
- EPUB3 支持 SVG；但旧阅读器（部分 Kobo / Android）支持不一致。策略：先只上 SVG，
  并在 `verify_epub.py` 增加"每个图片资源都在 manifest 中、media-type 正确、href 可解析"，
  一旦出现阅读器不兼容的证据再考虑 PNG 兜底（兜底意味着双资产，成本另算）。
- `--split-level=1` 拆章后，图片 href 是相对各章 HTML 的路径，pandoc 负责改写；
  验收必须实际打开产物确认图未丢，而不只看 manifest。

## 6. 两个“静默失败点”与判据口径

1. **PDF 的中文字体**：失败表现是"豆腐块 + 门禁全绿"。判据：`verify_pdf` 数图；
   制作规范：图内文字转路径或非中文。
2. **EPUB 的资源路径**：失败表现是"EPUB 里图没了 + pandoc 退出码 0"。判据：
   `verify_epub` 校验 manifest 与 href；构建脚本必须传 `--resource-path`。

这两点都不靠人工检查兜底，各配一条机检判据。

**计数口径（所有新判据统一）**：以合并稿里的图片引用数（`![…](assets/diagrams/…)`）为分母，
以 HTML 中实际渲染出的 `<figure class="diagram">` 数与 PDF/EPUB 里的图片对象数为分子；
两边相等才算通过。**不得**拿“图片数”与“图注总数”比：纯 ASCII 章没有图片，那样会误报。

**每条判据必须能红**：新增判据同时附一条故意造错的用例（删掉一张图、改错一个 href、
把 alt 与图注写成不一致），跑出红色才算判据完成。

### 6.1 三条判据的实现口径

| 实现点 | 口径 | 理由 |
| --- | --- | --- |
| HTML 侧计数 | `<figure class="diagram">` 个数，与 `<img>` 一一对应（一图一 figure 一 img） | 一张 figure 包多 img 会让两边对不上 |
| PDF 侧计数 | 每页 `/Resources/XObject` 里的**唯一图片对象**数量（按对象引用去重） | 同一图被多页引用时不得重复计 |
| EPUB 侧计数 | OPF manifest 里 `media-type=image/svg+xml` 的**唯一资源**数 | spine 多处引用同一资源不代表多图 |
| 排除项 | 封面图（`[paths] cover_image` 配了才存在）不计入分子也不计入分母 | 它不属于图号体系 |
| data URI 前缀 | 必须为 `data:image/svg+xml;base64,` | 写错不影响构建但图静默不显示 |
| 扩展名白名单 | `.svg` 区分大小写 | `Links.SVG` 在多数阅读器上不可靠 |
| 退出码 | 0 通过 / 1 判据失败 / 2 无法评估（缺产物、缺依赖） | 沿用 C-09 的脚本契约 |
| JSON 字段 | 新增字段与既有报告字段同名前缀（`images_*`），不重命名旧字段 | 不破坏既有消费方 |
| alt 与图注 | 图片的 `alt` 去除标记后必须与图注标题逐字相同 | 否则无障碍文本与目录信息会逐渐分叉 |

## 7. 资产、确定性与体积

- 资产路径与命名固定（见 5.1），禁止脚本生成后再改名，否则图号与文件名会错位。
- SVG 内部不得含时间戳、随机 id、外部引用；同一份源必须产出同一份字节。
- 资产进版本库；`file_length` 只管文本行数，不适用于 SVG，但要在评审中人工确认单图不超过
  一屏可读复杂度（超过就拆图，而不是继续加宽）。
- **SVG 必须能过校验**：合法 XML（`defusedxml` 已在依赖里）、不得含 `<script>`、不得引用
  外部资源（`http(s)://`、`<image>`、外部字体）；不合法的图在构建期就失败，而不是内联后弄坏 HTML。
- **内部不得含时间戳/随机 id**；base64 内联固定不分行，保证同一份源产出同一份字节。
- **单图体积上限**：单张 SVG 原始字节设一个可核的天花板（如超 256 KB 就拆图），
  避免一张图吞掉整个 `pdf_max_mb` 预算。
- **可读性下限**：图内最小字号不小于 8pt（按打印尺寸换算），否则纸面上等于无可读。
- **来源与许可**：图是自绘的还是引用的，在 SVG 的 `<desc>` 里写一句来源与许可；
  不新增旁的元数据文件。
- **元数据清理**：导出工具常写入时间戳/编辑器版本，需在入仓前删掉，否则两份同构图的 diff
  全是噪声，也破坏“同一份源同一份字节”。
- **缓存交互（关键）**：`render/html_cache.py` 的片段键目前只看章节 md 与渲染器源码。
  图片内联后，章节 md 没变而 SVG 变了时，片段会被误复用并产出过期内联图。因此片段键必须
  包含该章引用的全部资产内容哈希；资产新增/删除/改名与 `--full` 一并视为失效。
- **缓存的三条边界**：构建失败（资产缺失/非法）时不写缓存；`--full` 不光忽略读，也覆盖写；
  `prune()` 同时清理“资产已删除”的旧片段，避免孤立文件让下一次构建误判为已渲染。
- **单进程**：本项不改并发模型，`data/tmp/html-cache` 只由构建进程写；并发构建不在支持范围内。
- 构建输出必须报告：内联资产数量与字节数、PDF 页数、EPUB 体积，三项都在既有阈值内。

## 8. 门禁影响矩阵

| 脚本 | 影响 | 处理 |
| --- | --- | --- |
| `structure.py` | 图号来自图注文本 | 不改 |
| `figures.py` / `captions.py` / `figure_clusters.py` | 同上 | 不改词表与长度判据；`captions.py` 增加一条“alt 与图注一致”的轻判据 |
| `diagrams.py` | 只审 ASCII 围栏宽度 | 增加"图片型图源"计数并声明不受理，避免静默脱管 |
| `links.py` | 相对链接可解析 | 增加对 `assets/diagrams/*.svg` 的存在性检查 |
| `to_html.py` | 无图片语法；片段缓存键不含资产 | 新增图片分支 + data URI 内联 + 体积报告；片段键含资产哈希 |
| `to_pdf.py` / `print_pdf.py` | 随 HTML | 不改代码，仅补打印 CSS |
| `verify_pdf.py` | 只查字体/几何 | 增加图片数与图注数的一致性判据 |
| `to_epub.py` | 缺 `--resource-path` | 补参数并断言 pandoc 未丢图 |
| `verify_epub.py` | 不查图片资源 | 增加 manifest/href/media-type 校验 |
| `content_volume.py` | 逐章字节下限 | 不改（图片语法行会让体积只增不减） |
| `content_depth.py` | 代码摘录一致性 | 不改（图片引用不是代码摘录） |
| `gate_trace.py` | 每个门禁需在质量清单登记 | 新增判据要登记；`diagrams.py` 的“图片型不受理”不得被当成覆盖下降 |
| `perf_baseline.py` | 只记 `check_runner` 的步骤耗时 | 本项不依赖它：`make.py build` 的耗时与体积靠阶段 5 的人工记录 |
| `style_schema.py` | 配置结构校验 | 新增 `[paths] diagrams` 需同步 schema，否则键不生效 |
| 核对项 | TOC / 大纲 | 两者只取 heading，`<figure>` 不进目录，所以图形态变化不影响页数与大纲比对 |
| `scorecard.py` | 六维评分 | 图形态变化不得抬高/降低分数（只认图注与引用） |

## 9. 不做什么

- 不把既有 ASCII 图整体重画：ASCII 在纯文本审阅、diff、终端阅读上仍优于图片。
- 不引入图片作为**唯一**的图源形态：两种形态长期并存，图注与图号规则只有一份。
- 不为图片单独建一套编号体系：图号仍然只来自图注行。
- 不在图里放需要字体才能正确显示的中文（除非 text→path）。
- 不允许多章复用同一张图资产：图号与资产文件名一一对应，复用会让图号歧义。
- 不把 SVG 交给运行时渲染（Mermaid/JS），构建链不新增执行环境。

---

## 10. 降级与回滚

- 单张图出问题：把该图的图片引用换回 ASCII 围栏即可，其余图不受影响（两种形态并存是
  回滚的前提）；回滚后重跑 `make.py build` 与 `make.py check`，两项均绿才算回滚完成。
- 出口侧出问题（EPUB 丢图 / PDF 豆腐）：保留源图不动，回退该出口的参数或 CSS；
  若短期无法解决，先把该章图退回 ASCII，并把问题登记为待办。
- 判据先行：门禁改造与试点图必须同一个变更内落地，避免“图已上、判据还没有”的窗口。
- 回滚后残留的未引用资产必须删除（或先人工确认后入 ``.gitignore``），否则下一轮资产哈希
  会让片段缓存失效，意外拉长构建时间。
