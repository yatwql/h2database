# 源码分析文档通用规范

> 适用于"读源码 → 出文档"的任何项目，与具体语言、仓库、书名无关。
> 项目相关约定（本项目的章节、术语、图注细则）见 `managements/style-guide.md`；
> 目录与归属见 `managements/folder.md`。

## 1. 适用对象与目标

- **读者**：需要在不读完全部源码的前提下，判断"改哪里、会影响谁"的工程师。
- **目标**：让每个结论都能回到源码坐标，让每个章节都能独立阅读。
- **非目标**：API 手册、教程式入门、架构评审结论；这些由别的文档承担。

## 2. 四层信息阶梯（每章都必须齐备）

| 层次 | 回答的问题 | 必备内容 |
|------|-----------|---------|
| 版图 | 这一块有哪些组成？ | 包/模块表：位置、规模、职责一句话 |
| 类型 | 谁在承担职责？ | 核心类型表：职责、规模、公开面 |
| 入口 | 从哪里进入、往哪去？ | 关键 API ↔ 源码坐标（`file:line`） |
| 路径 | 该按什么顺序读？ | 阅读顺序 + 跨章衔接点 |

**验收**：四层缺一层即视为不合格；表格行数建议 ≤20 行，超出的用"其余见附录"收敛。

## 3. 事实要求（可机检）

1. 每个源码引用必须可解析：`org/.../File.java:行号` 或 `Class.method(`。
2. 引用的行号必须落在文件长度内；方法必须存在于该类。
3. 包级结论必须来自 `package-info` 或类注释；无注释时须标注为归纳。
4. 上游更新后，引用与坐标必须重生成，不接受"人工记忆"的修正。

## 4. 章节骨架（建议顺序）

```text
# 第N章 标题
> 本章导读（范围 / 读完能做到什么 / 前置知识）
> 术语参考（指向术语表）
N.1 版图    N.2 核心类型    N.3 入口与坐标    N.4 阅读路径
N.5 依赖方向（可选）   N.6 设计权衡   N.7 常见误区
N.x 术语对照   N.y 本章小结   N.z 延伸思考（≥4 题，含难度与回顾锚点）
N.w 阅读检查清单   N.v 延展阅读（跨章引用）
```

## 5. 图示与表格

- 图必须有独立成行的图注，图注用动宾结构（"展示/对比/拆解…"），长度 8–30 字。
- ASCII 图宽度不超过页面预算（默认 100 列，中日韩字符按 2 列计）。
- 表格优先于长段落；表格首列是被描述对象，末列是判断依据或坐标。

## 6. 术语与引用

- 术语首次出现应能在术语表命中；术语表条目需标明章节与相关术语。
- 跨章引用统一写 `详见第X章《实际 H1 标题》`，标题必须逐字一致。
- 同义词择一并用到底（如"页/page""快照/snapshot"不混用）。

## 7. 练习与可迁移性

- 每章 ≥4 题，难度分 ★/★★/★★★，题目要求"回到源码找证据"。
- 每题给提示与回顾锚点（§X.Y），不得只给答案。

## 8. 验收清单（十项）

| # | 检查 | 通过线 |
|---|------|--------|
| 1 | 结构门禁 | 全绿（章节/段落/图号/围栏/TOC） |
| 2 | 事实密度 | ≥15 个可解析源码坐标/章 |
| 3 | 信息阶梯 | 四层齐备 |
| 4 | 读者负担 | 单章 150–400 行，表 ≤20 行 |
| 5 | 术语衔接 | 每章 ≥5 个术语命中 |
| 6 | 交叉引用 | ≥1 次/章，断链 0 |
| 7 | 练习质量 | ≥4 题/章，难度齐备 |
| 8 | 图注与图示 | 新增违规 0 |
| 9 | 交付一致 | Markdown/HTML/PDF/EPUB 与源一致 |
| 10 | 可复现 | 两次构建产物逐字节一致 |

## 9. 与工具链的对应

本规范大部分可机检，对应脚本见 `manuals/how-to-use.md`：
`digest_source.py`（版图与坐标）、`plan_outline.py`（覆盖矩阵）、
`build_manuscript.py`（骨架渲染）、`audit/*`（结构、图注、链接、术语）、
`render/verify_pdf.py`、`render/verify_epub.py`（交付）。
