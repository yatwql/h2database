# 图注与章节范围的单一来源：迭代设计

> 软件：bookwright — 源码分析成书工具 v0.1
> 版本：v0.2-dev
> 定位：**图注与章节范围的设计说明**——图注解析为什么必须只有一份、章节范围为什么不能写死、改哪里、
> 哪些不动。动作与验收看同目录 `plan.md`。

---

## 1. 问题

两处"多处各写一份"的重复，属于同一个类别：**判据依赖的形状定义散落在消费者手里**。

1. **图注解析**：`**图 X-Y: 标题**` 的识别在 6 个模块里各写一份正则，且已经互不一致：
   `structure.py` 只认数字图号、`figures.py` 不带行尾锚点、`captions.py` 与 `figure_clusters.py`
   带 `\s*$`、`smart.py` 不带空白容忍、`readability.py` 有两份（前缀版与整行版）。
   后果：同一行图注在不同门禁里可能一个认一个不认，改一处不会同步其余。
2. **章节范围**：`structure.py` 以 12 章为前提（`range(1, 13)` 两处），章数变了就静默截断。

---

## 2. 设计

**形状只定义一次，消费者引用它。** 在 `lib/_mdutil.py`（唯一的文本工具层）定义：

| 名称 | 含义 |
| --- | --- |
| `FIGURE_LABEL` | 图注前缀（当前为"图"，也是将来多语种的接入点） |
| `FIGURE_ID` | 图号形状：`[A-Z0-9]+-\d+[a-z]*`（覆盖 `7-1`、`A-1`、`7-1a`） |
| `CHAPTER_FIGURE` / `APPENDIX_FIGURE` | 需要分组的两套形状（章号段、字母段） |
| `figure_caption(line)` | 解析一整行，返回 `(图号, 标题)` 或 `None` |
| `figure_ids(text)` | 抽取一段文本里的全部图号 |

消费者只从这些名字取形状：门禁不再自备正则；需要分组的消费者（`structure.py` 要章号、
`figures.py` 要计数）用共享形状拼自己的分组正则，而不是自己发明形状。

章节范围由配置推导：`_config.chapter_numbering()` 汇总所有文件的章号，`structure.py`
用它替掉 `range(1, 13)`。

---

## 3. 范围与不做

- 改：`lib/_mdutil.py`（新增形状与解析助手）、`audit/structure.py`、`audit/figures.py`、
  `audit/captions.py`、`audit/figure_clusters.py`、`audit/smart.py`、`audit/readability.py`。
- 不做：不改任何门禁的**判据**（阈值、词表、桥接规则、编号规则都不动），只把"形状"搬到一处；
  不改图注体例（`how-to-write.md` §14）；不做多语种（那是语言包扩展项，需要第二阶段）。
- 不改输出文案：门禁的提示与 JSON 字段保持原样，避免下游消费方被迫同步。

---

## 4. 风险

1. **等价性风险**：六个消费者原有正则的边界略有差异，收口后必须证明"结论不变"——
   用现有测试（structure/figures/captions/figure_clusters/smart/readability 各自的用例）
   作为等价性证据，门禁结论与之前逐条相同。
2. **行尾容忍**：共享整行正则统一带 `\s*$`，比 `smart.py` 原版更宽松；差异只在"行尾有空格"
   这种写法上，属放宽而非收紧，不会让原有通过项变红。
3. **章号推导空集**：若配置没有任何章节编号，`structure.py` 的逐章统计应退化为空字典而不是崩溃；
   验收里有一条覆盖它。
