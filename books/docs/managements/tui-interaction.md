# TUI 交互设计契约

> 适用于 `app/tui.py` 与其键位层 `app/keys.py`。与 `../manuals/how-to-use-tui.md`
> （面向使用者）互补：本文是**实现必须遵守的规则**，改交互先改这里。

## 1. 一条原则：一次按键 = 一次响应

不按回车。按下即生效，界面立刻有回音。回车只用于"执行光标所指项"这一个语义，
不再作为"提交输入"的手段。

## 2. 键位映射

| 键 | 语义 | 备注 |
| --- | --- | --- |
| `↑` / `↓` | 移动光标 | 首尾循环；兼容 `ESC [ A/B` 与 `ESC O A/B` 两种终端序列 |
| `Enter` | 执行光标项 | `\r` 与 `\n` 等价 |
| 数字键 `1`–`9` | 直达执行 | 同时把光标移到该项，保持"光标=上次操作" |
| `c` / `r` / `?` | 配置 / 重读配置 / 帮助 | 单键直接生效 |
| `l` / `L` | 源码 → 手稿（LLM 润色） | 字母键不区分大小写；菜单对该类行加琥珀色 `LLM` 徽标，避免与确定性的 `1` 混淆 |
| `q` / `0` / `Esc` / `Ctrl+C` | 退出 | 四条路径等价，均走干净退出 |
| 其他 | 无效按键 | 提示一行，菜单继续，不退出 |

字母快捷键**大小写不敏感**（`c`/`C`、`r`/`R`、`l`/`L`、`q`/`Q` 等价），
由 `app/keys.py` 的 `normalize()` 统一转换。

`Esc` 同时是"取消"：孤 ESC（后无序列字符）判定为取消，不会被误读成方向键前缀。

## 3. 反馈契约

任何一次执行都必须按顺序给出四段信息，缺一视为不合格：

1. **执行前**：`⠿ 正在执行 <名称>（<action>）…`，并立即 flush；
2. **执行后**：输出尾部最多 15 行（更早的行折叠成一行提示）；
3. **结果行**：`✓ 完成 / ✗ 失败`、`用时 x.xs`、`退出码 N`、`输出 K 行`；
4. **去处**：`详情见 books/logs/`，让操作者知道完整日志在哪。

不允许"静默执行"：命令跑完什么都不显示，等价于失败。

## 4. 确认契约

只对**耗时且重写大量产物**的动作要一次确认（当前仅 `deliver`），提示固定为
`[y/N]`，默认否；其余动作不打扰。确认文本不写"确定吗？"，要写清代价
（例如"会重建全部产物"）。

配置修改不弹二次确认，而是回显"已更新 `<键>` = `<值>`"。

## 5. 光标与布局契约

- 光标行前缀固定为 `❯`，其余行留一个空格，保证行宽不跳动；
- 进入界面时光标默认停在 `2`（手稿 → Markdown + HTML），回车即做最常见的下一步；
- 光标行文字用亮色（`PALETTE['cursor']`），未选中用常规色；
- 分组标题只做分隔，不可被光标选中；
- 上次执行结果保留在菜单下方，直到下一次按键被清空。

## 6. 非交互输入契约

`stdin` 不是终端时（管道、测试、CI）退化为行模式：读一行、取首字符、等价于
按一次键。因此 `printf 'q\n' | bookctl tui` 与真实终端行为一致，脚本化不会失效。

## 7. 一致性

- 键位、反馈、确认、颜色四处规则与 investor-review 的终端交互保持同一套习惯：
  单键生效、方向键导航、`Esc` 取消、非 tty 回退行模式。
- 颜色只表达语义（见 `app/tui.py` 的 `PALETTE`），新增界面不得引入色表之外的颜色。
