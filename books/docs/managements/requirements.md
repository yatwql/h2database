# 需求文档

> 软件：bookwright — 源码分析成书工具 v0.2
> 版本：v0.2
> 状态：已交付
> 定位：**要做什么、做成什么样算验收**——需求只说可观察的结果；不定义怎么做（看
> `technical.md`），也不写操作步骤（看 `docs/manuals/`）。

本文件是工程的第一步：它定义"要做出什么"，不定义"怎么做"、也不定义"怎么操作"。
因此全文不引用任何技术文档或用户文档；凡涉及验证与交付的判据，一律以**可观察的
结果**表述（产物存在、内容满足条件、检查通过或失败），而不是指向某个实现说明。

编号约定：`FR` 功能需求，`IR` 交互需求，`NFR` 非功能需求。需求只增不删；废弃需求
标注为"作废"并保留编号。

## 1. 项目目标

对**一套目标源码树**（语言与包前缀由书的配置声明）进行系统分析，产出面向开发者的中文技术文档，
使读者能够理解它的架构分层、核心数据流、关键数据结构与算法、并发与一致性、持久化与故障恢复、
性能与调优线索；并使这套文档本身长期可维护、可交付、可核验。

分析对象不是工具链的一部分：换一本分析报告，只需要换书的配置（`book.toml`、`base.json [sources]`），
工具链与本文的要求不变。

## 2. 交付物

| 产物 | 形态 | 交付时点 |
| --- | --- | --- |
| 章节正文 | Markdown 源文件，章节槽由书的配置声明 | 持续维护 |
| 附录 A | 端到端案例研究（一条读路径、一条写路径、一次故障恢复） | 与正文同批 |
| 附录 B | 跨小版本源码变更说明 | 与正文同批 |
| 后件 | 术语表、概念索引、参考文献（题为附录 C/D/E，不单独占章节编号） | 与正文同批 |
| 前件与后件 | 前言、版权页、阅读指南 | 与正文同批 |
| 合并稿 | 单一 Markdown 文件 | 每次构建 |
| HTML | 带侧边栏目录与印刷目录的网页版 | 每次构建 |
| PDF | A4、带大纲与可点击目录 | 交付阶段 |
| 印刷版 PDF | 章首装饰页、目录虚线对齐 | 交付阶段（按需单独生成） |
| EPUB | 面向电子阅读器，含导航 | 交付阶段 |
| 生成与检查工具 | 可重复执行的程序 | 持续维护 |
| 管理文档 | 需求、计划、规范、质量、变更记录 | 持续维护 |

产物数量、字数、图数等统计数字以封面页呈现的统计为准，本文件不重复维护。
编号口径：`book.toml` 只给附录 A/B 分配章节号；附录 C/D/E 是后件文件，按名称出现在目录里。

## 3. 内容范围

以下是要覆盖的**面**；每一面"必须写到什么程度"由 `content-standard.md` 定义（与具体
项目无关），具体覆盖到哪些章节、哪些包与哪些主题，由书的章节清单与包映射声明。本文不重复登记：

- 目标项目的定位、发展脉络与整体架构。
- 分层结构：对外接口层、核心引擎层、各内部子系统，以及它们的依赖方向。
- 各主要包的职责、关键类型与它们之间的关系。
- 核心流程：该项目的几条主链路（读、写、后台任务等，由书的覆盖表指定）。
- 关键数据结构与算法，以及它们服务的问题。
- 并发与一致性、持久化与故障恢复的机制与取舍。
- 性能相关的设计选择与调优入口。
- 源码阅读路线、调试入口与全书总结。
- 端到端案例与跨版本变更说明。

## 4. 功能需求

| 编号 | 需求 |
| --- | --- |
| FR-01 | 正文按书声明的章节清单连续编号，每章有唯一的 H1 标题；章节顺序稳定、可配置。 |
| FR-02 | 内容型小节至少 2 幅图，模板型小节至少 1 幅图；每幅图有唯一编号与图注。 |
| FR-03 | 关键论述给出源码文件名与行号，路径写法与目标源码树一致（包路径 + 文件名），可与源码逐条核对。 |

阅读顺序（`[chapters.numbering]`）与内容覆盖（`[chapters.coverage]`）是两张表：前者决定合并稿的
文件顺序与 H1 期望值，后者决定逐章统计（索引、术语、体量）统计哪些章号。
| FR-04 | 章节之间存在交叉引用；引用必须指向真实存在的章节或小节。 |
| FR-05 | 附录 C 覆盖正文高频术语，每条含释义、章节指引与相关术语。 |
| FR-06 | 附录 D 提供主条目、子条目与 see-also 三档索引，条目均指向真实章节。 |
| FR-07 | 每章末尾具备固定结构：本章导读、延伸思考、本章小结、延展阅读，四者顺序固定。 |
| FR-08 | 每章"延伸思考"至少 3 题，全书不少于 50 题；每题给出难度与类型标识、提示行，以及带小节或章节锚点的回顾行。 |
| FR-09 | 同一 ASCII 图内不混用框线风格；图宽不超过约定列数；行尾不留空白。既有超限图须显式登记，并在修订时收敛。 |
| FR-10 | 图注以动宾结构起首，长度在约定区间内；同一小节内连续出现的多幅图需有一句桥接叙述，点名这组图。既有不合规图注须显式登记，新增图注不得再违规。 |
| FR-11 | 附录 A 提供端到端案例：一条读路径、一条写路径、一次故障恢复，链路可追到源码坐标。 |
| FR-12 | 附录 B 说明相邻小版本之间影响本书论述的变更。 |
| FR-13 | HTML 版提供侧边栏目录与印刷目录，两级目录均与正文标题一一对应；字体按角色声明，不得写死某一操作系统的字体族。 |
| FR-14 | PDF 版为 A4、无旋转、字体全部嵌入（不得回落为 Type3 描边），含与正文标题一致的层级大纲，印刷目录可点击且跳转正确；正文行距与字号之比、文字占可印高度的比例须落在约定区间。 |
| FR-15 | EPUB 版 mimetype、容器、清单、阅读顺序与导航齐备，导航链接全部可达；每个正文文件恰好一个一级标题，图注不得被当作章节。 |
| FR-16 | 封面统计与正文一致：章节数、图数、行数等数字不得与正文实际内容矛盾。 |
| FR-17 | 术语与排版一致：同一概念全书写法统一；标题不带尾标点；中英文之间留空格。既有例外须显式登记，新增文字不得再违规。 |
| FR-18 | 代码摘录与源码一致：摘录的行号、方法与源码当前版本对得上；已漂移的引用必须显式登记。 |
| FR-19 | 换书、换操作系统、换字体集只改配置：字号与行距由栏宽与每行字数推导，不得写死某一本书或某一平台的参数；纸面与重排版面各按自身规则取字体（嵌入 vs 声明）。 |

## 5. 交互需求

面向"人怎么用"：作者写稿、审阅者复核、读者取用三种角色。

| 编号 | 需求 |
| --- | --- |
| IR-01 | 提供单一入口完成一次完整检查，不需要按顺序手工调用多个程序。 |
| IR-02 | 检查按改动范围分档：只改文档、只改测试、只改代码各有独立的检查集合；编辑期的单次检查不超过 5 秒。 |
| IR-03 | 分档只影响"现在跑什么"，不影响"什么算通过"：提交档与发布档始终检查全集。 |
| IR-04 | 失败输出可定位：直接给出文件与行号，或给出可执行的待办清单；退出码非 0 即失败。 |
| IR-05 | 检查与构建可离线完成，除首次安装依赖外不访问外网。 |
| IR-06 | 交互式入口、命令行入口与网页入口共享同一份状态与同一套动作，三者结果一致。 |
| IR-07 | 交互式入口的状态摘要控制在一屏之内，能看到当前阶段与最近一次结果。 |
| IR-08 | 任何耗时步骤都打印当前阶段；中途失败不吞掉已产生的结果。 |
| IR-09 | 已知问题的处置结果可读：被接受的问题列成清单，已消失的条目会被提示可以收缩。 |
| IR-10 | 一本书一份配置：同一套工具链可服务多本书，书与书之间不共享派生状态、基线与产物。 |
| IR-11 | 被分析的源码随书绑定：不在运行期切换源；多于一棵源树时按 label 区分，体量基线记录源指纹。 |
| IR-12 | 版本记录可追不膨胀：已发布版本的台账与已完成的迭代设计移入 `docs/archive/` 的版本目录，主文档只留当前开发段与索引。 |
| IR-13 | 一书多稿：同一本书的多份手稿（版本）各自有自己的派生状态、体量基线与产物名，互不覆盖；单版本时行为不变。 |
| IR-14 | 分析语言由配置声明，不由代码写死：新增一门语言＝一个适配器模块 + 注册表一行，后缀与坐标匹配都取 `sources.suffixes`；无包声明的语言（C）按目录切包，头文件声明过的符号才算公开 API。 |

## 6. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-01 | 内容不得静默塌陷：任一章节的体量与已认可基线相比不得低于约定比例；交付件的页数与体积同样受下限约束。 |
| NFR-02 | 可复现：同一输入连续两次构建的 HTML 产物完全一致。 |
| NFR-03 | 环境唯一：所有第三方依赖版本固定，交付流程只允许在项目自带的隔离环境中执行。 |
| NFR-04 | 质量存量受控：已知问题以可审阅清单管理；新出现的同类问题必须失败；清单只允许收缩或经评审后调整。 |
| NFR-05 | 性能预算：编辑期检查 ≤ 5 秒，提交档 ≤ 60 秒，全量检查 ≤ 5 分钟，PDF 交付 ≤ 10 分钟；其中性能门禁只做 advisory 提示（对比评审基线），硬预算由 CI 的墙钟记录丈量 |
| NFR-06 | 体积预算：PDF ≤ 12 MB，EPUB ≤ 10 MB。 |
| NFR-07 | 历史稿隔离：既往版本的稿子只以只读快照存在，不参与构建、不参与检查，可作为比对基准。 |
| NFR-08 | 配置外置：章节清单、阈值、词表、路径与预算全部来自配置文件，程序内不得内联这些值。 |
| NFR-09 | 可移植：Linux、macOS、Windows 三平台行为一致；不依赖本机编码、换行或绝对路径。 |
| NFR-10 | 零出站：检查与构建阶段不产生任何外部网络连接。 |
| NFR-11 | 可维护性：任一源文件与文档文件的长度受预算约束；超出时须拆分或说明理由。 |
| NFR-12 | 无过程痕迹：仓库中的文档、注释与配置只描述当前状态，不承载项目演进过程记录。 |

## 7. 非目标

- 不替用户选择分析对象：换一棵源树是换书的配置，不是改工具。
- 不做跨项目横向对比：一份文档只对一个源树负责。
- 不提供可运行的示例应用或性能基准结论。
- 不在文档中维护完整版本历史、完整问题清单或大段命令脚本。
- 不保证与上游尚未发布的分支同步。

## 8. 验收判据

本工程视为完成，当且仅当：

1. 交付物清单中的每一项都存在，且形态符合第 2 节描述。
2. 第 4 节的功能需求逐条成立；不成立项须登记为已知问题并注明原因。
3. 第 5 节的交互需求可被观察验证：单一入口可用、分档生效、失败可定位。
4. 第 6 节的非功能需求全部满足；性能与体积在预算之内。
5. 全书不存在未登记的内容退化：与已认可的体量基线相比，没有章节以静默方式缩减。

## 9. 需求变更

本文件是需求的唯一来源。需求增补以新编号追加，作废的需求保留编号并标注"作废"；
按版本发布的变更记录另行维护，不在本文件内展开。
