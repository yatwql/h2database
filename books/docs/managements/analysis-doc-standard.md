# 源码分析文档通用规范

> 软件：bookwright — 源码分析成书工具 v0.1
> 版本：v0.1
> 定位：**内容标准**——一本"读源码 → 出文档"的书，内容上必须满足什么。与语言、
> 仓库、书名都无关，换一份源码树照样适用。写法（句式、排版、图注措辞）见
> `style-guide.md`；阈值与判据的实际取值在 `data/config/style.json`，验收由质量
> 计划登记；工具如何实现这些判据见 `technical.md`。本文不重复这三者。

## 1. 适用对象与目标

- **读者**：需要在不读完全部源码的前提下，判断"改哪里、会影响谁"的工程师。
- **目标**：让每个结论都能回到源码坐标，让每一章都能独立阅读。
- **非目标**：API 手册、教程式入门、架构评审结论；这些由别的文档承担。

## 2. 四层信息阶梯（每章都必须齐备）

| 层次 | 回答的问题 | 必备内容 |
| --- | --- | --- |
| 版图 | 这一块有哪些组成？ | 包/模块表：位置、规模、职责一句话 |
| 类型 | 谁在承担职责？ | 核心类型表：职责、规模、公开面 |
| 入口 | 从哪里进入、往哪去？ | 关键 API ↔ 源码坐标（`file:line`） |
| 路径 | 该按什么顺序读？ | 阅读顺序 + 跨章衔接点 |

**验收**：四层缺一层即视为不合格。表格过长时用"其余见附录"收敛，具体行数预算在
配置里。

## 3. 事实要求

1. 每个源码引用必须可解析：`org/.../File.java:行号` 或 `Class.method(`。
2. 引用的行号必须落在文件长度内；方法必须存在于该类。
3. 包级结论必须来自 `package-info` 或类注释；无注释时须标注为归纳。
4. 上游更新后，引用与坐标必须重新生成，不接受"人工记忆"的修正。

这四条都可机检：坐标与符号的可解析性、摘录与源码的一致性各有一道门禁。

## 4. 章节骨架

```text
# 第N章 标题
> 本章导读（范围 / 读完能做到什么 / 前置知识）
> 术语参考（指向术语表）
N.1 版图    N.2 核心类型    N.3 入口与坐标    N.4 阅读路径
N.5 依赖方向（可选）   N.6 设计权衡   N.7 常见误区
N.x 本章小结   N.y 延伸思考   N.z 延展阅读
```

骨架中被强制的那部分（哪些段落必须存在、叫什么名字）由书籍配置的 `[sections]`
给出：本章导读、本章小结、延伸思考、延展阅读。本文只描述它们的位置与作用。

## 5. 图示与表格

- 图必须有独立成行的图注；图注说清"展示了什么关系"，而不是复述图里已有的字。
- ASCII 图宽度受列数预算约束（中日韩字符按 2 列计）。
- 表格优先于长段落；表格首列是被描述对象，末列是判断依据或坐标。

图注句式、动词表与列数上限的定义在 `style-guide.md` §14；具体取值在配置里，改配置即生效。

## 6. 术语与引用

- 术语首次出现应能在术语表命中；术语表条目需标明章节与相关术语。
- 跨章引用写明"详见第X章《实际 H1 标题》"，标题必须逐字一致。
- 同义词择一并用到底（如"页/page""快照/snapshot"不混用）。

## 7. 练习与可迁移性

- 每章都应有延伸思考，难度分 ★/★★/★★★，题目要求"回到源码找证据"，而不是复述结论。
- 每题给提示与回顾锚点（§X.Y），不得只给答案。
- 目标题量高于门禁下限：写的时候按目标写，门禁按下限判。

## 8. 内容验收清单

以下是内容维度的自查项，逐条回答"是/否"；其中可机检的部分由门禁判定，级别与
阈值以质量计划与配置为准。

| # | 检查 | 通过线 |
| --- | --- | --- |
| 1 | 结构完整 | 章节、必备段落、图号、围栏、目录成对且自洽 |
| 2 | 事实密度 | 关键论述带可解析的源码坐标，且与当前源码一致 |
| 3 | 信息阶梯 | 版图、类型、入口、路径四层齐备 |
| 4 | 读者负担 | 单章长度与表格行数在预算内 |
| 5 | 术语衔接 | 高频术语在术语表命中，并有章节指引 |
| 6 | 交叉引用 | 章间互引存在且断链为零 |
| 7 | 练习质量 | 题量达下限、难度齐备、每题有提示与锚点 |
| 8 | 图注与图示 | 图注说清关系，新增违规为零 |
| 9 | 交付一致 | Markdown / HTML / PDF / EPUB 与源一致 |
| 10 | 可复现 | 同一输入两次构建产物逐字节一致 |

## 9. 与工具链的关系

本文只定义内容标准；哪道门禁判哪一条、判到什么级别，登记在质量计划里；门禁本身
如何实现、依赖哪些层，属于技术设计。新增标准时补三处：本文一节、质量计划一行、
门禁一处实现——缺任何一处，标准就只停留在纸面。
