# DESIGN-TUI.md — 终端交互契约

> 软件：bookwright — 源码分析成书工具 v0.1
> 版本：v0.1-dev
> 定位：**终端界面的唯一判据**，作用于 `app/tui.py` 与其键位层 `app/keys.py`。
> 共有规则（身份/状态/颜色分工/文案基调）见 `DESIGN.md`，本文只写终端特有的部分；
> 使用者的操作说明属于用户文档，不在本文范围。

## 1. 一条原则：一次按键 = 一次响应

不按回车。按下即生效，界面立刻有回音。回车只用于"执行光标所指项"这一个语义，
不再作为"提交输入"的手段。

## 2. 屏幕分区

自上而下七段，顺序固定：

| 区 | 内容 | 说明 |
| --- | --- | --- |
| 标题带 | 软件名 + 中文名 + 工具版本；右端可带"更新 <日期>" | 身份区，用醒目色 |
| 路径带 | 当前层级（`主菜单 › 内容`），一级不显示箭头 | 任何时候都能回答"我在第几层" |
| 对象行 | 书名 + 版本 + 更新时间；源码版本 | 说明"正在为哪本书工作" |
| 状态行 | 语言、日志级别、LLM provider | 低饱和，供扫读 |
| 用量行 | `LLM 今日 ≈ x/上限 y`、`手稿 40,097 行（再少 5,049 行即判「内容变薄」）` | 两个「离危险多远」的数，进界面即可见；体量按行数算（与体积门禁同一口径：下限 = 已评审基线 × `floor_ratio`），**说后果而不是机制**——「再少 N 行即判『内容变薄』」比「体量/下限/余量」更容易读懂，也不用百分比（百分比会被读成增长率）；无基线/无上限时显示 `—` |
| 菜单 | 分组标题 + 可执行项，每项右侧给 `[键]` | 只有这里是饱和色 |
| 结果区 | 上次执行的四段反馈 | 与按钮区之间以空行分隔；显示期间 `0` 先收起结果，下一次按键即可继续 |

每次重绘前先归位并清屏（`\033[H\033[2J`），因此同一时刻屏幕上只有当前这一帧；
清屏只在终端且启用颜色时发出，管道与测试捕获到的输出保持纯文本。
框线用低饱和灰，**不参与强调**；行宽按显示宽度计算（CJK 与全角字符占两列），
框线不得因中英文混排而错位。

菜单下方**不渲染输入提示符**：`❯ ` 只作光标行前缀，不能单独出现在屏幕底部——一个孤立的提示符会让操作者以为要输入整段文本。
结果区显示时给出中性的收尾提示（`按任意键继续 · 0 收起结果回到菜单`），而不是再抛一个提示符。

## 3. 键位映射

| 键 | 语义 | 备注 |
| --- | --- | --- |
| `↑` / `↓` | 移动光标 | 首尾循环；兼容 `ESC [ A/B` 与 `ESC O A/B` 两种终端序列 |
| `Enter` | 执行光标项 | `\r` 与 `\n` 等价 |
| 数字键 `1`–`9` | 直达执行 | 同时把光标移到该项，保持"光标=上次操作" |
| 主菜单字母 `a/l/b/p/t/c/s/n` | 与 `1/2/3/4/5/6/7/8` 等价 | 大小写不敏感；只在主菜单生效，行内以 `1/a` 的形式同时显示两种键 |
| `c` / `r` / `?` | 配置 / 重读配置 / 帮助 | 单键直接生效 |
| `l` / `L` | 源码 → 手稿（LLM 润色） | 字母键不区分大小写；该行加琥珀色 `LLM` 徽标，避免与确定性动作混淆 |
| `0` / `Esc` | 收起结果 → 返回上一级 → 在主菜单上退出（按此顺序） | 结果在屏时先回菜单，不退出；二级目录再按 `0` 回上级；主菜单的 `0` 与 `q` 等价 |
| `q` / `Ctrl+C` | 在任何层级直接退出 | 不经过确认，走同一条干净退出路径 |
| 其他 | 无效按键 | 提示一行，菜单继续，不退出 |

字母快捷键大小写不敏感（`c`/`C`、`r`/`R`、`l`/`L`、`q`/`Q` 等价），由
`app/keys.py::normalize()` 统一转换。孤 `ESC`（后无序列字符）判定为取消，
不会被误读成方向键前缀。

## 3.1 两级结构

菜单只有两层，第二层以下不再往下分：

```text
主菜单  1 analyze · 2 analyze-llm · 3 build · 4 deliver · 5 质量 · 6 配置与状态
        7 切换书籍 · 8 新增书籍 · 0 退出
        （数字键另有字母快捷键：1/a · 2/l · 3/b · 4/p · 5/t · 6/c · 7/s · 8/n，大小写不敏感）
质量    1 check · 2 test · 0 返回
配置    1 status · 2 llm-ask · 3 配置项 · 4 LLM provider 优先级 · 5 doctor · 6 刷新事实块
        · 0 返回
配置项  逐项列出可写键 + 0 返回           （行来自 core.settings.list_settings）
优先级  按回退顺序列出 provider + 0 返回  （行来自 core.settings.provider_order）
书籍    列出可切换的书（书名 + 书根），当前一本以 ● 起首；数字键选定 + 0 返回
```

分级标准只有一个：**每天要按的动作放第一级，偶尔才打开的分组才收进二级**。
内容流水线（analyze / build / deliver）属于前者；质量与配置属于后者，一次进入后
可以连按几项再返回。

「新增书籍」也在第一级：按 `n` 依序问「书名」「源码目录或 git 地址」，随后调用
`core/scaffold.py` 在**当前书的 `data/book/` 下**建 `books/data/book/<书名>/`，源码是 URL 时
再克隆到 `books/data/srcref/<owner>__<name>/`；任一步失败都只报原因，不留下半本书。
「切换书籍」在第一级：多书并行时它和「构建」同一频次，藏进配置里等于每次多按两下。
「书籍」屏只在多本书可发现时才有意义：候选来自 `_config.candidate_books()`（当前书、
同目录兄弟书、从工作目录向上找到的书），切换立即生效并把结论写进状态行；只有一本时
该屏仍可打开但只列一行，避免让人以为还有别的可选。
模型的唯一来源是 `core/menu.py::SCREENS`：键、动作、标签、默认光标位置都在那里，
`app/tui.py` 只渲染。动态屏（配置项、优先级）的行由数据生成，但 `0 返回` 行与
其它屏一样由菜单层提供——**任何二级屏都必须有一行可按键的"返回上一级"**，不依赖
记忆某个保留键。

## 4. 反馈契约

任何一次执行都必须按顺序给出四段信息，缺一视为不合格：

1. **执行前**：`⠿ 正在执行 <名称>（<action>）…`，并立即 flush；
2. **执行后**：输出尾部最多 15 行（更早的行折叠成一行提示）；
3. **结果行**：`✓ 完成 / ✗ 失败`、`用时 x.xs`、`退出码 N`、`输出 K 行`；
4. **去处**：`详情见 books/logs/`，让操作者知道完整日志在哪。

不允许"静默执行"：命令跑完什么都不显示，等价于失败。

## 5. 确认契约

只对**耗时或会改写已有产物**的动作要一次确认，提示固定为 `[y/N]`，默认否；其余动作不打扰。
确认文本不写"确定吗？"，要写清代价：

| 动作 | 问什么 | 默认 |
| --- | --- | --- |
| `deliver` | 会重建全部产物 | 否 |
| `analyze-llm` | 整篇重写已有正文并用 LLM 润色导读/小结（旧文件先备份到 `data/tmp/`） | 否（只刷新事实块，正文不动） |

配置修改不弹二次确认，而是回显"已更新 `<键>` = `<值>`"。

## 6. 光标与布局契约

- 光标行前缀固定为 `❯`，其余行留一个空格，保证行宽不跳动；
- 每个屏各自记住光标位置；回到上级再进来，仍停在离开时的那一项；
- 各屏的默认光标：主菜单 `2 手稿 → Markdown + HTML`、质量与配置 `1`，
  即最常用的下一步（`menu.DEFAULT_ENTRY_KEY`）；
- 光标行文字用 `PALETTE['cursor']`，未选中用常规色；
- 分组标题只做分隔，不可被光标选中；
- 上次执行结果保留在菜单下方，直到下一次按键被清空。

## 7. 非交互输入契约

`stdin` 不是终端时（管道、测试、CI）退化为行模式：读一行、取首字符、等价于
按一次键。因此 `printf 'q\n' | bookctl tui` 与真实终端行为一致，脚本化不会失效。
无配色环境（非 tty 或 `NO_COLOR`）自动退化为纯文本，判据不变。

## 8. 颜色角色

`app/tui.py::PALETTE` 是唯一来源，键名即语义角色：

| 角色 | 用途 |
| --- | --- |
| `frame` | 框线与分隔 |
| `label` / `value` | 字段标签与取值 |
| `product` / `product_accent` | 软件身份 |
| `book` / `book_accent` | 书籍身份 |
| `group` | 菜单分组标题 |
| `key` | 可按键（唯一的饱和绿） |
| `ok` / `warn` / `error` | 三态 |
| `hint` | 次要提示、版本号、日期 |
| `cursor` / `cursor_bar` | 光标行与其前缀 |
| `llm_badge` / `llm_key` | 会消耗模型额度的动作 |

新增颜色必须先加角色名再使用，禁止在渲染处直接写颜色码。
