# DESIGN.md — 设计契约总纲

> 软件：bookwright — 源码分析成书工具 v0.1
> 版本：v0.1-dev
> 定位：**呈现面的共同契约**。它规定三处呈现面共享的视觉与语义规则，以及各自的
> 专项契约在哪里。改界面先读这里，再读对应专项契约。
> 三处呈现面分两类：**交互界面**（终端、网页控制台）与**输出面**（成书产物）。
> 交互界面就是三个渠道中的两个（第三个是 CLI，见 `technical.md` §4.7），三者
> 共用同一份动作表；成书产物只输出、不接收输入，因此不持有动作。
> 配套：`DESIGN-TUI.md`（终端）、`DESIGN-WEB.md`（网页控制台）、`style-guide.md`
> （成书产物的写作与排版规则）。实现与约束见 `technical.md`。

## 1. 一份契约为什么分四份

| 文档 | 守什么 | 读者 |
| --- | --- | --- |
| 本文 | 三处呈现面共有的语言：身份、状态、颜色、文案基调 | 所有改界面的人 |
| `DESIGN-TUI.md` | 「怎么按、按了会怎样、屏幕怎么分区」 | 修改 `app/tui.py`、`app/keys.py` 的人 |
| `DESIGN-WEB.md` | 页面与 JSON 接口的形状、状态的呈现、能加什么不能加什么 | 修改 `app/web.py` 的人 |
| `style-guide.md` | 成书产物里的写作、图注、排版规则 | 写手稿的人 |

分工原则：**共有规则只写一次**（本文），专项规则只写差异。任何专项文档重复本文的
内容即为冗余，应删除。

## 2. 共同原则

1. **工具面，不是营销面**。三个界面都为「做事」服务：信息密度与可扫读优先，
   拒绝装饰性插画、hero 大图、动效炫耀。
2. **身份与界面元件的色彩分工固定**。软件名用醒目色（终端亮青），书籍用暖色
   （终端暖黄），框线与标签用低饱和灰，**只有可操作的按键/按钮使用饱和色**——
   视线自然落到"能按的地方"。
3. **状态是一等公民**。成功、警告、失败各有固定语义色与固定措辞；不允许临时
   编造"好像出错了"这类模糊表达。三态定义为：`ok` 成功、`warn` 需注意但可继续、
   `error` 失败且需要动作。
4. **不静默**。任何一次操作完成后必须给出：做了什么、结果如何、详情在哪。命令
   跑完毫无输出，等价于失败。
5. **中文优先**。界面文案、状态提示、错误说明一律中文；专有名词保留英文原形。
6. **单一强调色**。每个界面只有一个强调色族；禁止第二个强调色。
7. **界面不做业务**。终端与网页的差异只在"怎么呈现、怎么接收输入"；能做什么由
   同一份动作表决定（CLI 亦然），规则由领域层持有。成书产物不在这个动作链上。

## 3. 跨界面语义对照

同一含义在三个界面上必须是同一种说法、同一种颜色语义：

| 语义 | 终端 | 网页控制台 | 成书产物 |
| --- | --- | --- | --- |
| 成功 | `✓ 完成` + 绿色 | JSON `code: 0` + 成功色 | 通过标记（`✅`） |
| 警告 | `!` 前缀 + 琥珀色 | JSON `code: 0` 且输出含告警行 | 警告标记（`⚠`） |
| 失败 | `✗ 失败` + 红色 + 退出码 | JSON `code != 0` + 失败色 | 失败标记（`❌`） |
| 身份 | 软件名 + 版本 | 页面标题 + 软件名 | 页眉/版权页 |
| 对象 | 书名 + 版本 + 更新时间 | `/api/status` 的输出文本 | 封面 |
| 详情去处 | `books/logs/` | 输出区完整文本 | 不适用 |

## 4. 颜色与排版来源

- 终端调色板只有一处：`app/tui.py::PALETTE`，键名即语义角色。新增颜色必须同时
  新增角色名，不得直接写颜色码。角色清单与用途只在 `DESIGN-TUI.md` §8 维护，本文
  不重复。
- 网页控制台与成书产物的样式内联在各自渲染处（`app/web.py::PAGE`、
  `render/to_html.py` 的样式段），规则是同样的：**颜色按角色使用，不按位置使用**。
- 成书产物的排版规则（字号阶梯、代码块、图注、表格）由 `style-guide.md` 规定；
  本文只管三个界面共享的部分。
